# 自動封鎖機制

## 觸發

後端 `procProtect.mjs` 於 `WWebSso` 啟動時初始化（被 `WWebSso.mjs:469` 帶入九個 opt 參數呼叫），於同一個 closure 內註冊四個獨立的 `setInterval` 背景 timer（每 2 秒執行一次），分別偵測：
1. 帳號登入失敗次數
2. Token 調用 API 次數
3. IP 調用 API 次數
4. IP 初次出現偵測（僅登記，不封鎖）

同時對外輸出（掛在 `pp` 物件上）：
- 給主流程呼叫的記錄函式：`loginByAccountAndPassword`（保護層）、`callApiByToken`、`callApiByIp`
- 給主流程呼叫的查詢函式：`getBlockedByAccount`、`getBlockedByIp`
- 取得 client IP 的工具：`getIpByHeaders`

## 重要流程

- **E2E-001**
  - title: 連續輸錯密碼觸發帳號自動封鎖
  - description: 驗證使用者於登入頁短時間內連續輸錯密碼次數超過設定上限後，A timer 於下一輪掃描將該帳號的 timeBlocked 寫入未來時間；待 timer 結算後再進登入頁、輸入正確帳密嘗試登入，UI 須顯示「帳號已暫時鎖定」之 i18n 訊息，且不會 redirect 至使用者資訊頁。spec 粒度規則：封鎖訊息為統一文案，不洩露「為何被鎖／剩多久解鎖」等內部狀態以防攻擊者推斷封鎖機制。
  - flow:
    - 測試資料：user `id-ab-block1-{lang}`（帳號 `ab-block1-{lang}` / 密碼 `Pw@abblock1A` / isActive='y' / timeVerified 有值 / timeExpired 未來 / timeBlocked 空）。
    - 操作：開乾淨登入頁（localStorage 無 token）→ 連續以「正確帳號 + 錯誤密碼」嘗試登入「上限 + 1」次 → 等待 A timer 結算寫入 timeBlocked → 再以「正確帳號 + 正確密碼」嘗試登入一次。
    - 驗證（最後一次嘗試後）：
      1. 語意：DB users.timeBlocked 為未來時間；當前 URL 不含 `view=user`（仍停留登入頁）；UI 出現對應 i18n 之「帳號已暫時鎖定」訊息。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-001-account-block-trigger.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-002**
  - title: 輸錯密碼後輸對一次失敗紀錄歸零
  - description: 驗證使用者連續輸錯「上限 − 1」次密碼後，第 N 次以正確密碼登入即可成功通過保護層；登入成功後 A 區塊會清空該帳號的 in-memory 失敗紀錄陣列，故 timeBlocked 不被寫入、不累計到後續觸發封鎖。outcome 為使用者轉跳至使用者資訊頁，且 DB 中 timeBlocked 仍為空字串。
  - flow:
    - 測試資料：user `id-ab-reset2-{lang}`（帳號 `ab-reset2-{lang}` / 密碼 `Pw@abreset2A` / isActive='y' / timeVerified 有值 / timeExpired 未來 / timeBlocked 空 / redir 帶 `?view=user&token={token}`）。
    - 操作：開乾淨登入頁 → 連續以「正確帳號 + 錯誤密碼」嘗試登入「上限 − 1」次 → 第「上限」次以「正確帳號 + 正確密碼」登入。
    - 驗證（等待 redirect 完成後）：
      1. 語意：當前 URL 含 `view=user`；待 A timer 至少跑完一輪後，DB users.timeBlocked 仍為空字串（失敗紀錄已歸零、未觸發封鎖）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-002-account-failure-reset.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-003**
  - title: 封鎖中帳號輸對密碼仍顯示封鎖訊息
  - description: 驗證已預先寫入未來時間 timeBlocked 的使用者，即使輸入正確帳密，保護層仍會於核心驗證之前以 timeBlocked 判定為封鎖中並 reject；UI 顯示對應 i18n 之「帳號已暫時鎖定」訊息，且不會 redirect 至使用者資訊頁。spec 粒度規則：封鎖訊息為統一文案，不洩露剩餘解鎖時間與封鎖原因。
  - flow:
    - 測試資料：user `id-ab-blocked-{lang}`（帳號 `ab-blocked-{lang}` / 密碼 `Pw@abblocked1` / isActive='y' / timeVerified 有值 / timeExpired 未來 / timeBlocked 預先寫入未來時間）。
    - 操作：開乾淨登入頁 → 以「正確帳號 + 正確密碼」嘗試登入。
    - 驗證：
      1. 語意：當前 URL 不含 `view=user`（仍停留登入頁）；DB users.timeBlocked 仍為未來時間；UI 出現對應 i18n 之「帳號已暫時鎖定」訊息。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-003-blocked-login-rejected.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-004**
  - title: 帳號封鎖時間到期後可正常登入
  - description: 驗證封鎖判定採「隱性解除」設計：使用者帳號預先寫入「現在 + 30s」之 timeBlocked，待該時刻過去後再行登入，保護層比對當前時間 > timeBlocked 即視為未封鎖、放行至核心驗證；不需要額外清空 timeBlocked 欄位。outcome 為使用者輸入正確帳密後成功登入並 redirect 至使用者資訊頁。
  - flow:
    - 測試資料：user `id-ab-expired-{lang}`（帳號 `ab-expired-{lang}` / 密碼 `Pw@abexpired1` / isActive='y' / timeVerified 有值 / timeExpired 未來 / timeBlocked 預寫為「創建後 30s」/ redir 帶 `?view=user&token={token}`）。
    - 操作：開乾淨登入頁 → 等待 timeBlocked 過期（保險加 buffer）→ 以「正確帳號 + 正確密碼」嘗試登入。
    - 驗證（等待 redirect 完成後）：
      1. 語意：當前 URL 含 `view=user`（封鎖時效已隱性解除、登入成功）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-004-block-expiry-implicit-unlock.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-005**
  - title: Token 高頻調用 API 致使 token 失效
  - description: 驗證同一登入 token 於短時間內以瀏覽器 Promise.allSettled 並行打 getSsoUserInfor 超過設定上限後，B timer 將該 user 寫入 timeBlocked 並刪除其所有 tokens 紀錄；後續再以同 token 呼叫 API 將回報 `invalid token`、reload 頁面後因 token 失效而落回登入頁、不會自動登入。spec 規則：Token 封鎖採「封鎖 user + 刪 token」而非在 token 上加封鎖欄位，後端統一回 `invalid token` 不分原因。
  - flow:
    - 測試資料：user `id-ab-token5-{lang}`（帳號 `ab-token5-{lang}` / 密碼 `Pw@abtoken5A` / 有效帳號可登入取得 token）。
    - 操作：開乾淨登入頁 → 登入並取得 token → 於瀏覽器內 Promise.allSettled 並行打 getSsoUserInfor 「上限 + 1」次 → 等待 B timer 結算（user 寫入 timeBlocked、tokens 紀錄被刪）→ 再呼叫一次 getSsoUserInfor → reload 頁面。
    - 驗證：
      1. 語意：最後一次 getSsoUserInfor 回報 state='error'、msg='invalid token'；DB tokens 該 userId 為 0 筆；DB users.timeBlocked 為未來時間；reload 後頁面落回登入頁、可見「Log in」/「登入」按鈕。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-005-token-block-trigger.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-006**
  - title: IP 高頻調用 API 致使 IP 被封鎖
  - description: 驗證同一 client IP 於短時間內以 Promise.allSettled 並行打 $fapi.getWebInfor 超過設定上限後，C timer 將該 IP 寫入 ips.timeBlocked 為未來時間；待 timer 結算後以同一 IP 進登入頁，連線層 verifyConn 直接 reject、SPA 卡在 Connecting 載入動畫。因正常登入過程中亦會短暫顯示 Connecting，故須等待 10s 後仍為 Connecting 才能斷定被擋下。本案例用 X-Forwarded-For 模擬虛擬 IP，避免封鎖測試自身來源 127.0.0.1。
  - flow:
    - 測試資料：user `id-ab-ipblock6-{lang}`（有效帳號）；虛擬 client IP `1.2.3.{100 或 200}`（eng / cht 各用不同尾數隔離）；ips 表初始無此 IP。
    - 操作：以 X-Forwarded-For 指定虛擬 IP → 開乾淨登入頁完成登入取得 token → 於瀏覽器內 Promise.allSettled 並行打 $fapi.getWebInfor 「上限 + 1」次 → 等待 C timer 結算 → 再以同一虛擬 IP 進登入頁 → 等 10s。
    - 驗證：
      1. 語意：DB ips 表有該虛擬 IP 紀錄、ips.timeBlocked 為未來時間；10s 後頁面內文仍含「Connecting」字串、不出現「Log in」/「登入」按鈕。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-006-ip-block-trigger.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與虛擬 IP 紀錄，保留 base seed。

- **E2E-007**
  - title: IP 封鎖中於連線層被擋
  - description: 驗證已預先寫入未來時間 ips.timeBlocked 的 IP，即便不主動發起高頻調用，連線層 verifyConn 仍會於每次請求同步查 ips.timeBlocked 直接 reject；SPA 卡在 Connecting 載入動畫無法進入登入表單。同 E2E-006 的等待 10s 偵測機制，避免與正常登入過程中的短暫 Connecting 混淆。
  - flow:
    - 測試資料：虛擬 client IP `1.2.3.{101 或 201}`（eng / cht 各用不同尾數隔離）；ips 表預先 insert 該 IP 並寫入未來時間之 timeBlocked。
    - 操作：以 X-Forwarded-For 指定虛擬 IP → 進登入頁 → 等 10s。
    - 驗證：
      1. 語意：10s 後頁面內文仍含「Connecting」字串、不出現「Log in」/「登入」按鈕（連線層持續 reject）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-007-ip-blocked-rejected.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化虛擬 IP 紀錄，保留 base seed。

- **E2E-008**
  - title: IP 封鎖時間到期後可進入登入頁
  - description: 驗證 IP 封鎖同採「隱性解除」設計：ips.timeBlocked 預寫為「現在 + 10s」，待該時刻過去後再以同一 IP 進登入頁，連線層比對當前時間 > timeBlocked 視為未封鎖、放行；SPA 可順利結束 Connecting 並渲染登入表單。
  - flow:
    - 測試資料：虛擬 client IP `1.2.3.{102 或 202}`（eng / cht 各用不同尾數隔離）；ips 表預先 insert 該 IP，timeBlocked 為「創建後 10s」。
    - 操作：以 X-Forwarded-For 指定虛擬 IP → 等待 timeBlocked 過期（含 buffer）→ 進登入頁。
    - 驗證：
      1. 語意：頁面已渲染登入表單、可見「Log in」/「登入」按鈕（封鎖時效隱性解除）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-008-ip-expiry-implicit-unlock.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化虛擬 IP 紀錄，保留 base seed。

- **E2E-010**
  - title: 新 IP 首次成功登入自動補登記至 IPs 表
  - description: 驗證 D 區塊「IP 初次偵測」設計：使用者以全新虛擬 IP 完成登入後，D timer 比對 kpIpCallApi 與 ips 表差集，將新 IP 以 ds.ips.funNew 產生不含 timeBlocked 的 oip 物件並 insert；此屬純登記、非封鎖，使用者於登入流程中無任何異常觀察、正常 redirect 至使用者資訊頁。
  - flow:
    - 測試資料：user `id-ab-ip9-{lang}`（有效帳號 / redir 帶 `?view=user&token={token}`）；虛擬 client IP `1.2.3.{103 或 203}`（eng / cht 各用不同尾數隔離）；ips 表初始無此 IP。
    - 操作：以 X-Forwarded-For 指定虛擬 IP → 開乾淨登入頁 → 以「正確帳號 + 正確密碼」登入 → 等待 D timer 結算。
    - 驗證（等待 redirect 完成後）：
      1. 語意：當前 URL 含 `view=user`（登入成功）；DB ips 表有該虛擬 IP 紀錄、ips.timeBlocked 為空字串（純登記、未封鎖）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-010-new-ip-registration.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與虛擬 IP 紀錄，保留 base seed。

### B. Token 調用 API 次數封鎖

```
B01  API handler 內每次請求皆呼叫 pp.callApiByToken(token)  [WWebSso.mjs:819,855,891,927,971]
B02      kpTokenCallApi[token].push(現在時間)  [procProtect.mjs:321]
B03  背景 timer (每 2 秒) 掃描 kpTokenCallApi  [procProtect.mjs:344]
B04      lockingForTokenCallApi 互斥旗標  [procProtect.mjs:347]
B05      timeStart = 現在 - minForTokenCallApi 分鐘  [procProtect.mjs:353]
B06      逐 token 過濾, 僅保留判準時間窗內的紀錄  [procProtect.mjs:360]
B07      若判準時間窗內呼叫次數 > numForTokenCallApi:  [procProtect.mjs:373]
B08          呼叫 blockAccountByToken(token)  [procProtect.mjs:377]
B09              以 token 查 tokens 表取得 userId  [procProtect.mjs:263]
B10              以 userId 取 user 物件 (p.getGenUserByUserId)  [procProtect.mjs:280]

B12              timeBlocked = 現在 + minBlockForTokenCallApi 分鐘  [procProtect.mjs:295]

```

> 備註：Token 封鎖採「封鎖 user + 刪 token」而非在 token 上加封鎖欄位，後續請求帶該 token 查不到 tokens 紀錄就會直接得 `invalid token` 而失效；同帳號下次重新登入也會被 `users.timeBlocked` 擋下。

## 封鎖判定語意

`getBlockedByUser` 與 `getBlockedByOip` 共用同一套邏輯：

| `timeBlocked` 欄位狀態 | 比對結果 | 回傳 |
|------------------------|----------|------|
| 為空字串 `''` | - | `false`（未封鎖） |
| 合法 ISO 時間且 `當前 <= timeBlocked` | 仍在封鎖區間 | `true`（封鎖中） |
| 合法 ISO 時間且 `當前 > timeBlocked` | 封鎖時效已過 | `false`（自動解除） |
| 其他非法值 | - | `reject` |

「解鎖」為隱性：不需要把 `timeBlocked` 清空，時間一到自動視為解除，省去額外寫入並避免競態。

## 重複封鎖保護

三個 `blockXxx` 函式皆在更新 `timeBlocked` 前先檢查當前是否已在封鎖區間，若仍在封鎖中**直接跳出，不延長封鎖時間**。

設計理由：避免暴力流量在封鎖中持續觸發 timer 不斷把封鎖時間往後延，造成事實上「永久封鎖」。

邊界規則：
- 「次數 > 上限」才觸發封鎖，「次數 = 上限」不觸發
- 「已在封鎖中再次觸發」等於不延長封鎖時間，原 `timeBlocked` 不變
- 隱性解除：到期後不主動清 `timeBlocked` 欄位，僅靠比對當前時間判定

## i18n 訊息粒度規則

後端任何封鎖相關 reject 訊息與前端任何顯示文字皆走 i18n（不寫死語言），對應關係如下：

| 觸發情境 | 對應 key 區位（grep 提示） | 顯示位置 | 粒度規則（spec） |
|---|---|---|---|
| 帳號封鎖中嘗試登入 | `server/procLang.mjs` 內含 `loginAccountBlocked` 之 key（與 PageLogin 帳號狀態相關） | `PageLogin.vue` `.err` 紅字 | 統一「帳號已暫時鎖定」訊息，不洩露「為何被鎖／剩多久解鎖」等細節（避免攻擊者推斷封鎖機制） |
| 帳號登入密碼錯誤（尚未觸發封鎖） | `server/procLang.mjs` 內 `failedLoginForCatch` 等價 key（與登入失敗對應） | `PageLogin.vue` `.err` 紅字 | 統一「帳號或密碼錯誤」訊息，不洩露「帳號不存在 vs 密碼錯誤」（避免帳號列舉攻擊） |
| Token 失效（被刪 / 過期 / 觸發 B 區塊封鎖後） | 後端核心層回 `invalid token` 字串（搜 `server/` 內 `invalid token`） | 前端 fapi 收到 err 後一般清 localStorage token 並回登入頁 | 後端統一回 `invalid token`，不分「不存在 / 已過期 / 被封鎖刪除」 |
| IP 封鎖中發出任何請求 | （無對應 i18n key、無前端訊息） | `verifyConn` 直接 return false → hapi 連線層阻斷；SPA 仍處於 `Connecting...` 載入狀態（搜 `server/procLang.mjs` 內 `csIng` 等價 key） | **無特定錯誤訊息**，僅可由「SPA 卡 Connecting 超過 10s 仍未進登入頁」推斷被擋 |
| IP 首次出現（D 區塊登記） | 無 | 無使用者觀察 | 純後端自動補登記，使用者無感 |

## 參數來源

本流程涉及以下執行期參數，**讀取順序（測試與 server 行為一致）：`settings.json` 覆寫值 > `server/WWebSso.mjs` opt 預設值（無覆寫才採用）**。

| 概念 | 來源（優先序） | 測試影響 |
|---|---|---|
| 帳號失敗次數上限 | `settings.json` `numForAccountLoginFailed` → `server/WWebSso.mjs` opt 預設 | 觸發 case 須真打「上限+1」次失敗才會觸發 A timer 封鎖 |
| 帳號失敗判準時間窗（分鐘） | 同上 `minForAccountLoginFailed` → opt 預設 | 失敗紀錄保留時長；逾此時間窗內的舊紀錄會被 timer 裁切 |
| 帳號封鎖時長（分鐘） | 同上 `minBlockForAccountLoginFailed` → opt 預設 | 觸發後 DB `users.timeBlocked` 寫入「現在 + 該分鐘數」 |
| Token 調用 API 上限 | 同上 `numForTokenCallApi` → opt 預設 | 觸發 case 須真打「上限+1」次 API 才會觸發 B timer 封鎖 |
| Token 調用判準時間窗（分鐘） | 同上 `minForTokenCallApi` → opt 預設 | 同帳號失敗時間窗概念，套用至 token 調用紀錄 |
| Token 封鎖時長（分鐘） | 同上 `minBlockForTokenCallApi` → opt 預設 | 觸發後 DB `users.timeBlocked` 寫入「現在 + 該分鐘數」（透過 token 反查 user） |
| IP 調用 API 上限 | 同上 `numForIpCallApi` → opt 預設 | 觸發 case 須真打「上限+1」次（須走 verifyConn 路徑的 API，如 `$fapi.getWebInfor`／`/api/main`，不能用獨立 hapi route） |
| IP 調用判準時間窗（分鐘） | 同上 `minForIpCallApi` → opt 預設 | 同上時間窗概念，套用至 IP 調用紀錄 |
| IP 封鎖時長（分鐘） | 同上 `minBlockForIpCallApi` → opt 預設 | 觸發後 DB `ips.timeBlocked` 寫入「現在 + 該分鐘數」 |
| Timer 掃描間隔 | hardcode 於 `server/procProtect.mjs`（不可由 settings 覆寫） | 觸發後等待至少「該間隔 + 1s buffer」才能觀察到 timer 寫入結果 |
| 時間戳格式 | code 統一 `dayjs` ISO 8601 含 `+08:00` offset | 測試 mock `timeBlocked` 時須用相同格式（否則 ISO 解析 fail 走 reject 路徑） |
| `kpIpCallApi` 清空入口 | `settings.json` `cleanKpIpCallApiForToken` 識別 token + `/api/cleanKpIpCallApi` route（僅放行本機連入） | e2e 與 server 為獨立進程，無法直接清 in-memory state，須透過此 route 觸發 `pp.cleanKpIpCallApi()` |

實際數值 → 寫測試時讀 `settings.json` 對應 key；若無 → 讀 `server/WWebSso.mjs` 內該 opt 的預設值。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：4 個 timer 各自獨立運作（A 帳號 / B Token / C IP / D IP 登記），每 2 秒掃描。登入路徑於 protect 層先查 `timeBlocked` → 反之放行至核心驗證；API 路徑於 `verifyConn` 同步查 IP `timeBlocked`，封鎖中於連線層直接擋下。
- **粒度**：
  - 帳號封鎖（UI 顯示「帳號已暫時鎖定」固定訊息）/ Token 失效（前端清 LS 回登入頁）/ IP 連線層擋下（SPA 卡 Connecting）三類觀察粒度不同。
  - 不洩露「為何被鎖」「剩多久解鎖」「帳號是否存在」「token 是否曾存在」。
- **邊界**：
  - 「次數 > 上限」才觸發封鎖；「次數 = 上限」不觸發。
  - 已在封鎖中再觸發**不延長** `timeBlocked`（避免暴力流量造成事實上「永久封鎖」）。
  - 隱性解除：到期後不主動清 `timeBlocked`，僅靠比對當前時間判定。
  - Token 封鎖採「封鎖 user + 刪 token」而非在 token 上加封鎖欄位；後續請求拿不到 tokens 紀錄即 `invalid token`。
  - 取不到 client IP 一律 fail-closed（以封鎖處理）。
- **契約**：
  - in-memory 紀錄（`kpAccountLoginFailed` / `kpTokenCallApi` / `kpIpCallApi`）server 重啟後歸零；`users.timeBlocked` / `ips.timeBlocked` 為持久化紀錄。
  - Timer 互斥：每 timer 進入前先檢查 `lockingForXxx` 旗標，上一輪未結束直接 return；`finally` 內必歸零。
  - 時間戳格式統一 `dayjs` ISO 8601 + `+08:00`；其他非法字串走 reject 路徑。
