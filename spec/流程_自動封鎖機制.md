# 自動封鎖機制

## 觸發

後端 `procProtect.mjs` 於 `WWebSso` 啟動時初始化（被 `WWebSso.mjs:498` 帶入九個 opt 參數呼叫）。帳號登入失敗封鎖採**即時判定**：於 `loginByAccountAndPassword` 失敗當下同步計數並判封鎖（無背景 timer）。另於同一個 closure 內註冊三個獨立的 `setInterval` 背景 timer（每 2 秒執行一次），分別偵測：
1. Token 調用 API 次數
2. IP 調用 API 次數
3. IP 初次出現偵測（僅登記，不封鎖）

同時對外輸出（掛在 `pp` 物件上）：
- 給主流程呼叫的記錄函式：`loginByAccountAndPassword`（保護層）、`callApiByToken`、`callApiByIp`
- 給主流程呼叫的查詢函式：`getBlockedByAccount`、`getBlockedByIp`
- 取得 client IP 的工具：`getIpByHeaders`（`X-Forwarded-For` 第一個非空段須為合法 IP 才採用，`IPv4:port` 與 `[IPv6]:port` 去 port 取 IP（C03b），否則退回連線位址並限流記 warn，見 C03a；信任邊界屬部署契約，見 ADR-040、ADR-089）

## 重要流程

- **E2E-001**
  - title: 連續輸錯密碼觸發帳號自動封鎖
  - description: 驗證使用者於登入頁短時間內連續輸錯密碼次數「超過」設定上限後（門檻為 `>`，即上限 + 1 次失敗才觸發），保護層於該次失敗當下「即時」將該帳號的 timeBlocked 寫入未來時間；隨即再進登入頁、輸入正確帳密嘗試登入仍登入失敗、停留登入頁，UI 顯示統一登入失敗訊息，且不會 redirect 至使用者資訊頁。spec 粒度規則：被封鎖的登入回應與「密碼錯誤」「帳號不存在」完全一致（統一訊息，anti-enum），不洩露「帳號是否存在／是否被鎖／為何被鎖／剩多久解鎖」等內部狀態；故「以正確密碼登入仍失敗」即為封鎖已生效之判準。
  - flow:
    - 測試資料：user `id-ab-block1-{lang}`（帳號 `ab-block1-{lang}` / 密碼 `Pw@abblock1A` / isActive='y' / timeVerified 有值 / timeExpired 未來 / timeBlocked 空）。
    - 操作：開乾淨登入頁（localStorage 無 token）→ 連續以「正確帳號 + 錯誤密碼」嘗試登入「上限 + 1」次（門檻 `>`，第「上限 + 1」次失敗當下即時寫入 timeBlocked）→ 再以「正確帳號 + 正確密碼」嘗試登入一次。
    - 驗證（最後一次嘗試後）：
      1. 語意：DB users.timeBlocked 為未來時間；當前 URL 不含 `view=user`（仍停留登入頁）；UI 出現統一登入失敗訊息（與密碼錯誤同文案）。
      2. 視覺：與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-001-account-block-trigger.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user，保留 base seed。

- **E2E-005**
  - title: Token 高頻調用 API 致使 token 失效
  - description: 驗證同一登入 token 於短時間內以瀏覽器 Promise.allSettled 並行打 getSsoUserInfor 超過設定上限後，B timer 將該 user 寫入 timeBlocked 並刪除其所有 tokens 紀錄；後續再以同 token 呼叫 API 將回報 key `tokenExpired`、reload 頁面後因 token 失效而落回登入頁、不會自動登入。spec 規則：Token 封鎖採「封鎖 user + 刪 token」而非在 token 上加封鎖欄位，後端對外統一回 key `tokenExpired` 不分原因（對齊 ADR-006 anti-information-leakage；checkToken catch 路徑統一映射，原 _checkToken reject 之 `invalid token` / `duplicate tokens` 字串不對外洩漏）。
  - flow:
    - 測試資料：user `id-ab-token5-{lang}`（帳號 `ab-token5-{lang}` / 密碼 `Pw@abtoken5A` / 有效帳號可登入取得 token）。

      1. 語意：最後一次 getSsoUserInfor 回報 state='error'、msg='tokenExpired'（ADR-006 統一，機器可讀 key，非人類語言字串）；DB tokens 該 userId 為 0 筆；DB users.timeBlocked 為未來時間；reload 後頁面落回登入頁、可見「Log in」/「登入」按鈕。

- **E2E-006**
  - title: IP 高頻調用 API 致使 IP 被封鎖
  - description: 驗證同一 client IP 於短時間內以 Promise.allSettled 並行打 $fapi.getWebInfor 超過設定上限後，C timer 將該 IP 寫入 ips.timeBlocked 為未來時間；待 timer 結算後以同一 IP 進登入頁，連線層 verifyConn 直接 reject、SPA 卡在 Connecting 載入動畫。因正常登入過程中亦會短暫顯示 Connecting，故須等待 10s 後仍為 Connecting 才能斷定被擋下。本案例用 X-Forwarded-For 模擬虛擬 IP，避免封鎖測試自身來源 127.0.0.1。getWebInfor 為免 token 端點，無需登入即可調用，故本案例不包含登入步驟。

    - 測試資料：虛擬 client IP `1.2.3.{100 或 200}`（eng / cht 各用不同尾數隔離）；ips 表初始無此 IP（getWebInfor 為免 token 端點，不需使用者帳號）。

      1. 語意：DB ips 表有該虛擬 IP 紀錄、ips.timeBlocked 為未來時間；進登入頁後該頁之 API 請求收到連線層拒絕（回應標頭 `Return-Msg: permission denied`）；10s 後頁面內文仍含「Connecting」字串、不出現「Log in」/「登入」按鈕。
         - 修改留痕（2026-09-28）：補「收到連線層拒絕」一項——原僅以「10s 後仍為 Connecting」推斷被擋，機器負載高、正常連線本身慢於 10s 時會誤判為被擋（測試假通過）；連線層未通過時套件於 /api 回應帶 `Return-Msg: permission denied`（`node_modules/w-converhp/src/WConverhpServer.mjs` 之連線層拒絕回應 `permission`、`routeSpec.mjs` 之 `st200`），以此確認伺服器確實拒絕。10s 仍為使用者觀察期，照等。E2E-007 同。修改留痕（2026-10-14）：原載行號 `WConverhpServer.mjs:1139`、`routeSpec.mjs:22` 為 w-converhp 2.1.6 之位置，2.1.9 起位移，改為不帶行號之引用；回應標頭行為不變（ADR-085）。
      2. 視覺：框住「連線中」指示整顆（轉圈圖示與「Connecting」/「連線中」文字之聯集），與 baseline `test/pics/autoblock/autoblock-{eng,cht}-E2E-006-ip-block-trigger.png` 視覺一致（pixelmatch 容差）。
         - 修改留痕（2026-09-28）：視覺原未寫框住對象，而程式之文字目標選擇器（`div[style*="margin-left:10px"]`）因瀏覽器序列化為 `margin-left: 10px` 永不命中，框只剩轉圈圖示、文字在框外（技能 §7.3-3 框整顆）；轉圈圖示原遇截圖填黑成黑方塊，改貼去動畫之靜態影格（技能 §8.2 手冊用圖不填黑）。E2E-007 同。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化虛擬 IP 紀錄，保留 base seed。

## 封鎖判定語意

`getBlockedByUser` 與 `getBlockedByOip` 共用同一套邏輯：

| `timeBlocked` 欄位狀態 | 比對結果 | 回傳 |
|------------------------|----------|------|
| 為空字串 `''` | - | `false`（未封鎖） |
| 合法 ISO 時間且 `當前 <= timeBlocked` | 仍在封鎖區間 | `true`（封鎖中） |
| 合法 ISO 時間且 `當前 > timeBlocked` | 封鎖時效已過 | `false`（自動解除） |
| 其他非法值 | - | `reject` |

「解鎖」為隱性：不需要把 `timeBlocked` 清空，時間一到自動視為解除，省去額外寫入並避免競態。

## 重複封鎖保護

三個 `blockXxx` 函式皆在更新 `timeBlocked` 前先檢查當前是否已在封鎖區間，若仍在封鎖中**直接跳出，不延長封鎖時間**。

設計理由：避免暴力流量在封鎖中持續觸發封鎖判定不斷把封鎖時間往後延，造成事實上「永久封鎖」。

邊界規則：
- 「次數 > 上限」才觸發封鎖（實作為 `nrecs > numForXxx`，次數超過上限才封鎖，達到上限但未超過不封鎖）
- 「已在封鎖中再次觸發」等於不延長封鎖時間，原 `timeBlocked` 不變
- 隱性解除：到期後不主動清 `timeBlocked` 欄位，僅靠比對當前時間判定

實際數值 → 寫測試時讀 `settings.json` 對應 key；若無 → 讀 `server/WWebSso.mjs` 內該 opt 的預設值。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **多人同時編輯之表鎖**（2026-10-23，原則 10；跨清單規則見 `流程_多人同時編輯.md`，帳本 R-CONC-01）：帳號封鎖（登入失敗達門檻、權杖呼叫超限）於 `[tokens, users]` 兩把表鎖內「再驗身分 → 重讀使用者 → 判斷是否已封鎖 → 寫 `timeBlocked` → 撤銷名下全部 token」同鎖完成（再驗身分：登入失敗封鎖須失敗登入所針對之帳號仍屬該使用者且啟用中；權杖呼叫超限封鎖須該 token 仍在庫內、仍是使用者 token 且擁有者未變——等鎖期間被後台升為應用系統金鑰、換擁有者、改名或已登出者皆不封鎖，2026-10-23 外審 sol#3 後補），寫入經 w-serv-orm 且只改不增（讀到後該使用者被刪則不新增殘缺列），最後修改者 `userIdUpdate` 記常數 `system`；IP 封鎖與新 IP 登錄計時器於 `ips` 表鎖內讀取與寫入，亦記 `system`。`timeBlocked` 為雙方欄位：被自動封鎖後，載入在封鎖之前的後台清單頁存檔即被拒（不再把封鎖以舊值解除）；封鎖撤銷之 session token 亦不會因後台存舊金鑰清單而復活。封鎖寫入失敗之 log（`fun-blockAccount` 的 `errBlock`）因改經 w-serv-orm，文字為其固定字串（如 `failed to save data`）。

- **驗證順序**：帳號登入失敗封鎖 (A) 已改為即時判定（於失敗當下同步計數並判封鎖，無背景 timer）；Token (B) / IP (C) 封鎖仍各自由獨立 2 秒 timer 掃描，另有 IP 初次偵測 (D) timer（僅登記不封鎖）。登入路徑於 protect 層先查 `timeBlocked` → 反之放行至核心驗證，核心驗證失敗當下即同步判定是否達封鎖門檻；API 路徑於 `verifyConn` 同步查 IP `timeBlocked`，封鎖中於連線層直接擋下。
- **粒度**：
  - 帳號封鎖（UI 顯示與登入失敗相同之統一訊息，不透露封鎖狀態）/ Token 失效（前端清 LS 回登入頁）/ IP 連線層擋下（SPA 卡 Connecting）三類觀察粒度不同。
  - 不洩露「為何被鎖」「剩多久解鎖」「帳號是否存在」「token 是否曾存在」。
- **邊界**：
  - 「次數 > 上限」才觸發封鎖（實作為 `nrecs > numForXxx`）。
  - 已在封鎖中再觸發**不延長** `timeBlocked`（避免暴力流量造成事實上「永久封鎖」）。
  - 隱性解除：到期後不主動清 `timeBlocked`，僅靠比對當前時間判定。
  - Token 封鎖採「封鎖 user + 刪該 user 全部 token」而非在 token 上加封鎖欄位（與帳號登入失敗封鎖同為 multi-session 強制全部登出）；後續請求拿不到 tokens 紀錄，`checkToken` 對外統一回 key `tokenExpired`（`_checkToken` 內部 `invalid token` 不對外洩漏）。
  - 取不到 client IP 一律 fail-closed（以封鎖處理）。
  - 來源 IP 取 `X-Forwarded-For` 第一個非空段，須為合法 IP（`net.isIP`，長度 ≤ 64）才採用且原樣不改寫（不剝 `::ffff:`、不改大小寫，`ips` 表以原字串精確比對封鎖列）；唯一之正規化是去 port：`IPv4:port`、`[IPv6]:port` 取 IP 本身，同一 IP 不同 port 計為同一 IP（2026-10-20 run02 更正，原載「帶 port 退回連線位址」不成立）；去後仍非 IP 或非此兩種形式、以及非 IP（如 `length`、`constructor`、含標記字串、`unknown`、`1.2.3.4:abc`）不採用，退回連線位址並限流記 warn（2026-10-20，ADR-089）。信任邊界維持：標頭真實性由最外層受信任之反向代理 / 防火牆保證，本套件不做防偽造，不改取最右、不提供 `trustProxy`（使用者 2026-10-20 裁示，延續 ADR-040）。
- **契約**：
  - in-memory 紀錄（`kpAccountLoginFailed` / `kpTokenCallApi` / `kpIpCallApi`）server 重啟後歸零；三者於剪枝時，窗口內無紀錄之鍵一併刪除（R-CNT-01，2026-10-20；此前 `kpTokenCallApi` / `kpIpCallApi` 只剪紀錄、鍵永久殘留）；`users.timeBlocked` / `ips.timeBlocked` 為持久化紀錄。
  - Timer 互斥與錯誤收斂：四個 timer 皆經 `wrapTimer` 包裝——上一輪未結束時再觸發即略過；回呼之同步拋錯與 reject 一律攔下記 `srLog.error`（event `timer-error`），結束（不論成敗）即釋放，下一輪照常（R-ERR-01，ADR-085；2026-10-20 更正：原載之 `lockingForXxx` 旗標已不存在）。
  - 時間戳格式統一 `dayjs` ISO 8601 + `+08:00`；其他非法字串走 reject 路徑。
  - 封鎖寫入逐筆檢查（ADR-080）：w-orm 系列 save / del 遇單筆失敗不 reject，三種封鎖之寫入皆經逐筆檢查；寫入 `timeBlocked` 失敗時仍刪除該帳號全部令牌（A、B 皆然；依意圖 fail closed），失敗以 srLog.error 記錄（event `fun-blockAccount` / `fun-blockAccountByToken` / `fun-blockIpByIp`）；對使用者之訊息不變，封鎖未寫入者於下次觸發條件成立時再嘗試。
