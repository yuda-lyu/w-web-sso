# 後台變更使用者資訊流程

## 觸發

管理員於 LayoutContentUsers.vue 後台 Users list 對既有列就地修改 account / name / email / description / from / redir 等文字欄位，切換 isAdmin / isActive 勾選，調整 timeVerified / timeExpired / timeBlocked 時間欄位，或拖拉列改變順序，再點「儲存」批次提交至後端。

## 重要流程

> 編號規則:
> - `**E2E-NNN**`: UI baseline 測試, 對應 `test/e2e-modifyuser.test.mjs` + `test/pics/modifyuser/modifyuser-{lang}-E2E-NNN-*.png`
> - `**API-NNN(待補)**`: 編號預留, 尚無 e2e 待未來補 (API 契約測試)

- **E2E-001** 管理員於後台修改既有列欄位, 儲存成功（既有 password hash 由後端在 ltdtDiffByKey 前還原回 row 不被洗掉; userIdUpdate 與 timeUpdate 由 procOrm save 自動覆寫為操作者 id 與 now; userId 與 timeCreate 保留原值; 儲存成功後前端緊接重拉 getUsersList, 表格刷新顯示後端寫入的 userIdUpdate=操作者 id、timeUpdate=now、order 重排等）
- **E2E-002** 管理員於後台儲存時將 account 修改為空, 前端 isError 攔下無法儲存
- **E2E-003** 管理員於後台儲存時將 account 修改為與表中其他列重複, 前端 isError 攔下無法儲存
- **E2E-004** 管理員於後台儲存時將 email 修改為空, 前端 isError 攔下無法儲存
- **E2E-005** 管理員於後台儲存時將 email 修改為格式錯, 前端 isError 攔下無法儲存
- **E2E-006** 管理員於後台儲存時將 email 修改為同表內重複, 前端 isError 攔下無法儲存
- **E2E-007** 管理員於後台儲存時將 redir 修改為空, 前端 isError 攔下無法儲存
- **E2E-008** 管理員於後台儲存時, 把自己列的 isAdmin 由 'y' 改為 'n', 前端以 CheckYes modal 顯示「不可解除自己 admin 權限」之語系化訊息並不送出（後端為第二道防線同條訊息 reject）
- **E2E-009** 管理員於後台儲存時, 把自己列的 isActive 由 'y' 改為 'n', 前端以 CheckYes modal 顯示「不可停用自己帳號」之語系化訊息並不送出（後端為第二道防線同條訊息 reject）
- **E2E-010** 管理員於後台儲存時 email 經前端通過, 但 ltdtmapping 後仍被後端 ckKey('email') 全表掃出重複, 後端 reject
- **E2E-011** 管理員於後台點儲存時 token 已過期 / 已被刪, 後端 reject
- **E2E-012** 管理員於後台修改 timeVerified 任一時間欄位, 以 timemsTZ 格式寫回 row, 並於儲存時走 diff 群組同步至 DB
- **E2E-013** 管理員於後台修改 timeExpired 任一時間欄位, 以 timemsTZ 格式寫回 row, 並於儲存時走 diff 群組同步至 DB
- **E2E-014** 管理員於後台修改 timeBlocked 任一時間欄位, 以 timemsTZ 格式寫回 row, 並於儲存時走 diff 群組同步至 DB
- **E2E-015** 管理員於後台拖拉列調整順序, 儲存時後端 resetOrder=true 依新陣列順序重指派 order=k+1
- **API-001(待補)** 管理員以非 admin token 呼叫 updateUsersList API, 後端 funCheckAdmin 判否, 與「真過期」共用同一 reject 訊息（不洩露身分檢查細節）

## 執行流程

### 一、就地編輯欄位（資料表 cell-render）

```
account / email / redir / name / description / from
    aggrid 內建 cell editor 直接輸入文字 (kpCellEditable 定義);
    cell 顯示警告 icon 表示有 errItemsBy* 偵測到錯誤;
    輸入完成 → rowsChange → vo.isModified=true

password
    顯示為「重設密碼」按鈕, 不接受就地輸入

isAdmin / isActive
    checkbox 形式; click 走 $dg.toggleItemIsAdminById / toggleItemIsActiveById
        → toggleItemByKeyAndId(key, id) 切 'y' / 'n', set 至 opt.rows[kr].<key>
        → vo.refresh() 觸發 cell 重渲染, vo.isModified=true

timeVerified / timeExpired / timeBlocked
    左側狀態指示器顯示 isVerified / isExpired / isBlocked (綠勾 / 紅叉) 反映目前 row 狀態;
    右側 WTimeminute 日期時間選擇器 @input → handleCellTimeInput(key, id, timeNew)
        → 解析後以 timemsTZ 格式寫回 row 對應欄位
        → vo.refresh(), vo.isModified=true

順序
    account 欄啟用 kpRowDrag.account=true, 可拖拉列調整 opt.rows 順序;
    觸發 rowsChange → vo.isModified=true
```

### 二、即時前端驗證（computed）

前端 computed 對每列做粒度驗證，產生 cell 警告 icon + tooltip，並聚合為 `isError` 字串供 saveUsers 攔截。粒度規則詳「i18n 訊息粒度規則」章節。

```
errItemsByAccount   每列檢查 account 空值與同表重複, 寫入 kpErr[<value>] = 對應錯誤訊息
errItemsByEmail     每列檢查 email 空值 / isEmail 格式 / 同表重複
errItemsByRedir     每列檢查 redir 空值

isError computed（整體錯誤訊息, 第一層攔截）
    依序取 errItemsByAccount → errItemsByPassword → errItemsByEmail → errItemsByRedir
    第一條具體錯誤訊息 (cell tooltip 級訊息, 非 category title);
    cellFieldErr 在 cell 顯示警告 icon + tooltip 細節錯誤
```

### 三、儲存（saveUsers）

```
001  管理員點紅底「儲存」按鈕（僅 isEditable && isModified 顯示）
002  $ui.updateLoading(true)
003  檢查 isError
004      非空字串:
005          hideLoading + await showCheckYes(isError) 後 return（不送後端）
006  rows = vo.opt.rows
007  檢查 rows 是否為空 → 為空 hideLoading + await showCheckYes(對應訊息) return
008  自我鎖死保護（前端第一道）:
009      尋找 rows 內 row.id === userSelf.id
010      若該列 isAdmin !== 'y' → hideLoading + await showCheckYes(cannotDemoteSelf) return
011      若該列 isActive !== 'y' → hideLoading + await showCheckYes(cannotDisableSelf) return
012  剝除 transient flag _isNew (不送後端)
013  vo.$fapi.updateUsersList(token, lang, rows) 批次提交
014      handler 帶入 funCheckAdmin 後呼叫 p.checkTokenAndUpdateUsersList(token, lang, rows, opt)
015          checkToken({ fun: funCheckAdmin })
016              token 為空 / 過期 / 無效 → reject
017              token 有效但 funCheckAdmin 回 false（非 admin）→ b2=false → reject
018                  （注意: 此路徑不分歧錯誤訊息, 與真過期共用同一字串）
019          getUserByToken 取操作者 → operatorId
020          自我鎖死保護（後端第二道, 與前端同條訊息）:
021              rows 內找操作者 row, 若 isAdmin !== 'y' → reject(cannotDemoteSelf)
022                                     若 isActive !== 'y' → reject(cannotDisableSelf)
023          updateUsersList(rows, { lang, operatorId }) 委派
024              updateTabItems('users', rows, 'id', { resetOrder: true, lang, operatorId })
025                  ltdtmapping(rows, ds.users.keys) 補齊缺失欄位
026                  resetOrder: rows 依陣列順序重指派 order = k+1
027                  ckKey('id'): 表內 id 不可為空或重複 → reject
028                  ckKey('email'): 表內 email 不可為空或重複 → reject
029                  ltdtOld = woItems.users.select() 取 DB 既有資料
030                  既有 row password 保留: 將 ltdtOld 內對應 id 的 password (hash) 寫回 rows 該列
031                      （getUsersList 已 strip password, 前端送回的 password 是 '', 此步避免覆蓋既有 hash）
032                  ltdtDiffByKey(ltdtOld, rows, 'id') 偵測有差異的列, 收進 diff 群組
033                  diff 群組（既有 row 有變動）:
034                      procOrm(operatorId, 'users', 'save', r.diff)
035                          procOrm 內部對 save 群組自動覆寫:
036                              userIdUpdate = operatorId
037                              timeUpdate = now
038                          （userId / timeCreate 不被覆寫, 保留原始建立資訊）
039                          （password 已在步驟 030 還原為 DB hash, save 時 merge 不會覆蓋）
040                  return ltdtNew (剝除 password 欄位避免 hash 經 API 洩漏)
041  .catch err → errTemp = err
042  errTemp 非 null:
043      hideLoading + await $dg.showCheckYes(`<userSaveUsersFail>: ${errTemp}`) 後 return
            （改用 modal 強制 admin 點擊確認, 避免 transient toast 漏看後端錯誤訊息）
044  $fapi.getUsersList(token) 重拉同步, 覆寫 vo.users
045      （讓 userIdUpdate=operatorId、timeUpdate=now、order 重排等後端寫入結果立即顯示）
046  isModified = false（紅底儲存按鈕收起）
047  hideLoading + await showCheckYes(<userSaveUsersSuccess>)
```

### 四、衍生操作（同一表共用 saveUsers 路徑）

```
toggleItemIsAdminById / toggleItemIsActiveById
    checkbox click → 切 'y'/'n'，isModified=true
    儲存時走 diff 群組（procOrm save）;
    若被切的列 id === userSelf.id 且新值非 'y', 儲存階段會被自我鎖死保護擋下

handleCellTimeInput (timeVerified / timeExpired / timeBlocked)
    WTimeminute @input → 以 timemsTZ 格式寫回 row 對應欄位, isModified=true
    儲存時走 diff 群組（procOrm save）

rowDrag (透過 kpRowDrag.account=true 啟用)
    拖拉列 → opt.rows 陣列順序變動 → rowsChange → isModified=true
    儲存時 updateTabItems({ resetOrder: true }) 由後端依新陣列順序重指派 order=k+1
```

### 五、可變更／不可變更欄位邊界（純 spec）

| 欄位 | 可否就地變更 | 邊界規則 / 後端處理 |
|---|---|---|
| account | 可（cell editor）| 不可空、表內不重複（前端 errItemsByAccount 攔下；後端 ckKey 不額外檢查 account）|
| name | 可（cell editor）| 無限制 |
| email | 可（cell editor）| 不可空、需 isEmail 格式、表內不重複；後端 `ckKey('email')` 全表再檢查 |
| description / from | 可（cell editor）| 無限制 |
| redir | 可（cell editor）| 不可空 |
| isAdmin | 可（checkbox）| 自我鎖死保護：不可將自己改為非 'y'（前後端兩道）|
| isActive | 可（checkbox）| 自我鎖死保護：不可將自己改為非 'y'（前後端兩道）|
| timeVerified / timeExpired / timeBlocked | 可（WTimeminute）| timemsTZ 格式寫回 row，procOrm save merge 寫入 |
| order | 可（拖拉）| 後端 resetOrder=true 依新陣列順序重指派 order=k+1；前端送回的 order 值會被覆寫 |
| password | 不接受就地輸入（顯示為「重設密碼」按鈕）| 後端 saveUsers 在 ltdtDiffByKey 前以 ltdtOld 對應 id 的 hash 還原 row.password，避免前端送回空字串把 DB hash 洗掉 |
| id | 不可（kpHeadHide，偵測鍵）| ckKey('id') 確認不重複 |
| userId / timeCreate | 不可（前端不渲染為輸入元件）| procOrm save 不覆寫此兩欄位，保留原始建立資訊 |
| userIdUpdate / timeUpdate | 不可（前端不渲染為輸入元件）| procOrm save 自動覆寫為操作者 id 與 now |
| isForceChangePw / tokenVerify | 不在 tabKeysShow / tabKeysPick 內 | — |

## i18n 訊息粒度規則

| 觸發情境 | 對應 key 區位（grep 提示）| 顯示位置 | 粒度規則（spec）|
|---|---|---|---|
| 帳號欄位空 | `server/procLang.mjs` 找 `userAccountEmpty` | cell 警告 icon + tooltip | 單一訊息告知帳號空 |
| 帳號同表重複 | `server/procLang.mjs` 找 `userAccountDuplicate` | cell 警告 icon + tooltip | 不洩露重複對象 |
| email 欄位空 | `server/procLang.mjs` 找 `userEmailEmpty` | cell 警告 icon + tooltip | 單一訊息告知 email 空 |
| email 格式錯 | `server/procLang.mjs` 找 `userEmailError` | cell 警告 icon + tooltip | 單一訊息告知 email 格式不符 |
| email 同表重複 | `server/procLang.mjs` 找 `userEmailDuplicate` | cell 警告 icon + tooltip | 不洩露重複對象 |
| redir 欄位空 | `server/procLang.mjs` 找 `userRedirEmpty` | cell 警告 icon + tooltip | 單一訊息告知 redir 空 |
| 解除自己 admin 權限 | `server/procLang.mjs` 找 `cannotDemoteSelf` | CheckYes modal（前端先擋）+ 後端 reject（同訊息）| 前後端統一 |
| 停用自己帳號 | `server/procLang.mjs` 找 `cannotDisableSelf` | CheckYes modal（前端先擋）+ 後端 reject（同訊息）| 前後端統一 |
| 後端 token 過期 / 非 admin | `server/procLang.mjs` 找 token 過期相關 key（與 funCheckAdmin 判否共用同一訊息）| CheckYes modal，前綴 `userSaveUsersFail` | 不分歧：身分檢查失敗與真過期共用，不洩露差別 |
| 後端 ckKey('email') 重複 | 與 `userEmailDuplicate` 同訊息（產品設計上同 UI 文字）| CheckYes modal，前綴 `userSaveUsersFail` | 前後端訊息一致 |
| 儲存成功 | `server/procLang.mjs` 找 `userSaveUsersSuccess` | CheckYes modal | — |
| 儲存失敗（包裝層）| `server/procLang.mjs` 找 `userSaveUsersFail` | CheckYes modal | 作為後端 reject 訊息的前綴 |

實際 key 名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴。

## 參數來源

本流程涉及以下執行期參數，**測試讀取順序：settings.json 覆寫值 > WWebSso.mjs opt 預設**：

| 概念 | 來源（優先序）| 測試影響 |
|---|---|---|
| 使用者欄位 schema（哪些欄位存在、欄位預設值、kpHeadHide 隱藏項等）| `src/schema/users.mjs` | test setup 建 user 與 modify 後 DB 斷言基準 |
| salt（hashPassword）| `settings.json` 對應 key → 預設值 | 比對「password hash 未被洗掉」時須使用同 salt |
| token 有效期 | `settings.json` 對應 key | 測試 token 構造時的 `timeEnd` 計算 |

實際數字 / 預設值 → 寫測試時讀 `settings.json` 對應 key 或 `src/schema/users.mjs` 的 funNew。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：前端 computed `errItemsBy*` → 前端 `isError` 聚合攔截 → 前端自我鎖死保護 → 後端 `checkToken`（含 funCheckAdmin）→ 後端 `checkTokenAndUpdateUsersList` 自我鎖死保護 → `ckKey('id')` / `ckKey('email')` → procOrm save 寫入。任一層 reject 即整批不落地。
- **粒度**：account / email 「空」與「重複」分開告知；token 失效與身分不足共用同一訊息（不洩露身分檢查）；前後端攔截訊息一致。
- **邊界**：
  - password 不可由本流程修改（顯示為「重設密碼」按鈕，由獨立流程處理）。後端 saveUsers 在 ltdtDiffByKey 前以 DB 既有 hash 還原 row.password，避免前端送回空字串把 DB hash 洗掉。
  - 自我鎖死保護：rows 內若包含操作者本人，不可將自己 `isAdmin` 或 `isActive` 改為非 'y'（前端 + 後端兩道）。
  - userId / timeCreate 保留原值，不被覆寫；userIdUpdate / timeUpdate 由 procOrm save 自動覆寫為操作者 id 與 now（audit 不接受前端送來的值）。
- **契約**：
  - `updateUsersList` 走批次 upsert：整表 `ltdtDiffByKey` 一次同步 add / diff / del，任一驗證錯誤即整批不落地。即使 admin 只改一列，ckKey 仍對全表掃描。
  - 拖拉列順序變動 → 後端 `resetOrder=true` 依陣列順序重指派 order=k+1，前端送回的 order 值被覆寫；一次拖拉可能讓多列同時進入 diff 群組。
  - 儲存成功後立即重拉 `getUsersList` 同步 audit fields 與 order。
  - API 回傳前剝除 password 欄位，避免 hash 從 API 流出。
  - token 不因 user 資料更新而失效（token 表獨立，不級聯）。
