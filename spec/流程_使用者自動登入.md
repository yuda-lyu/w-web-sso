# 使用者自動登入流程

## 觸發

App.vue mounted 時自動執行。檢查 localStorage 是否有快取的 token，有則嘗試自動登入。

## 重要流程

- **E2E-001**
  - title: 已登入使用者開啟登入頁自動轉跳 redir
  - description: 驗證使用者於 localStorage 已存在有效 token、且帳號為啟用狀態並設定有效 redir 欄位時, 開啟登入頁 (無 view 參數預設 view=login, useRedir=true) 後, App.vue mounted 觸發 autoLogin, 經 checkToken 與 getUserByToken 驗證皆通過後依 user.redir 自動轉跳至目標位址, 使用者觀察到的最終視覺終態為已離開登入頁、頁面不再出現 Log in / 登入 按鈕。
  - flow:
    - 測試資料：user `id-autologin-ok`（帳號 `autologin-ok` / `isActive='y'` / `redir` 帶 `?view=user&token={token}` / `timeExpired` 未來 / `timeBlocked` 空）+ 有效 token（`timeEnd` 未來 60 分鐘）寫入 localStorage `ksso:userToken`。
    - 操作：先到 baseUrl 設好 localStorage token → 再導向乾淨 baseUrl（無 view 參數, 預設 `view=login`）→ App.vue mounted 自動觸發 autoLogin。
    - 驗證（等待 autoLogin 完成 + redirect 完成後）：
      1. 語意：DOM 上不應再出現 password input（已離開登入頁進入 user view）。
      2. 視覺：與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-001-ok-redir.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-002**
  - title: view=backstage 自動登入後停留後台
  - description: 驗證 admin 使用者以 `view=backstage` 開啟頁面、localStorage 已存在有效 token 且帳號為啟用狀態時, autoLogin 經 checkToken 與 getUserByToken 驗證通過後, 因 useRedir=false 不執行 redir 轉址, 使用者停留於後台頁面 (Statistics)。view=backstage 要呈現完整後台 dashboard 必須由 admin (`isAdmin='y'`) 觸發, 非 admin 會被 LayoutContent isAdmin filter 擋成只剩使用者資訊 (即 E2E-009 情境), 兩案構成「同為 view=backstage、admin vs 非 admin 之視圖權限分流」對照。因後台「存取活動監測」區塊起含即時圖表 (canvas) 跨進程 warm/cold 狀態不同會造成 byte 漂移, baseline 與 verify 兩端均對該區塊以下填黑遮罩, 只比對上半靜態區域。
  - flow:
    - 測試資料：admin user `id-autologin-ok-admin`（帳號為啟用狀態 `isActive='y'` / `isAdmin='y'`） + 有效 token 寫入 localStorage。
    - 操作：先到 baseUrl 設好 admin user 之 localStorage token → 再導向 `?view=backstage` → App.vue mounted 自動觸發 autoLogin → 留在後台。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上不應再出現 password input（已進入後台, 離開登入頁）。
      2. 視覺：對「存取活動監測」區塊起所有後續區塊填黑遮罩後, 與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-002-ok-backstage.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-003**
  - title: view=user 自動登入後停留使用者頁
  - description: 驗證使用者以 `view=user` 開啟頁面、localStorage 已存在有效 token 且帳號為啟用狀態時, autoLogin 經 checkToken 與 getUserByToken 驗證通過後, 因 useRedir=false 不執行 redir 轉址, 使用者停留於使用者資訊頁。
  - flow:
    - 測試資料：user `id-autologin-ok`（同 E2E-001 之啟用 user） + 有效 token 寫入 localStorage。
    - 操作：先到 baseUrl 設好 localStorage token → 再導向 `?view=user` → App.vue mounted 自動觸發 autoLogin → 留在使用者資訊頁。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上不應再出現 password input（已進入使用者頁, 離開登入頁）。
      2. 視覺：與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-003-ok-user.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-004**
  - title: 無快取 token 自動登入靜默回登入頁
  - description: 驗證使用者過往未登入 (localStorage 無 token) 時開啟登入頁, autoLogin 取不到 token 後以 `reject('no token')` 靜默結束, App.vue 外層 .catch 接住後將使用者帶回登入頁。依 spec 粒度規則, 此情境不顯示任何具體錯誤訊息, 視覺終態為單純的登入頁。本案例 baseline 亦為 E2E-006/E2E-007/E2E-008 共用之基準圖。
  - flow:
    - 測試資料：localStorage 無 `ksso:userToken` (token 設為空字串)。
    - 操作：先到 baseUrl 清空 localStorage → 再導向乾淨 baseUrl → App.vue mounted 自動觸發 autoLogin → autoLogin 取不到 token 直接 reject → App.vue 回登入頁。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上應出現 `Log in`（eng）/`登入`（cht）按鈕（仍在登入頁）。
      2. 視覺：與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-004-no-token.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-005**
  - title: redir 欄位為空顯示無有效轉址錯誤
  - description: 驗證 autoLogin 成功（token 有效、user.isActive='y'）但 user.redir 為空字串、且當前 URL 進入登入頁 (useRedir=true) 時, 流程在 redir 分流階段判定無有效轉址, 透過 `failedLoginForNoRedir` 顯示無有效轉址 alert 訊息後回到登入頁。
  - flow:
    - 測試資料：user `id-autologin-no-redir`（帳號 `autologin-no-redir` / `isActive='y'` / `redir=''` 空字串 / `timeBlocked` 空）+ 有效 token 寫入 localStorage。
    - 操作：先到 baseUrl 設好 localStorage token → 再導向乾淨 baseUrl（預設 `view=login`, useRedir=true）→ App.vue mounted 自動觸發 autoLogin → 通過 checkToken/getUserByToken 但 redir 為空。
    - 驗證（等待 autoLogin 完成且 WAlert 仍顯示中時截圖）：
      1. 語意：DOM 上應出現 `Can not get the url for redirection`（eng）/`無有效轉址`（cht）文字。
      2. 視覺：與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-005-no-redir.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-006**
  - title: 帳號已停用自動登入靜默回登入頁
  - description: 驗證使用者過往已成功登入但帳號被改為非啟用 (`isActive='n'`) 時, autoLogin 通過 checkToken 後呼叫 getUserByToken, 因內部以 `isActive:'y'` 查詢而查無使用者 reject。為避免洩露「user 是否被停用」給未驗證瀏覽器端, 依 spec 粒度規則本案例視覺終態統一為靜默回登入頁, 與 E2E-004 共用同一張 baseline。
  - flow:
    - 測試資料：user `id-autologin-inactive`（`isActive='n'`）+ 有效 token 寫入 localStorage。
    - 操作：先到 baseUrl 設好 localStorage token → 再導向乾淨 baseUrl → App.vue mounted 自動觸發 autoLogin → getUserByToken 因 isActive 條件不符 reject → 外層 .catch 接住後回登入頁。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上應出現 `Log in`（eng）/`登入`（cht）按鈕（已回登入頁）。
      2. 視覺：與 E2E-004 共用 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-004-no-token.png` 視覺一致（pixelmatch 容差）（防洩露停用狀態, 視覺等同無 token 情境）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-007**
  - title: localStorage token 在 DB 已不存在
  - description: 驗證 localStorage 仍有 token 快取但後端資料庫已查無對應 token（例如使用者已登出或被管理員清除）時, autoLogin 呼叫 checkToken, 後端因查無此 token 而 reject（後端 token 鏈對外統一回 key `'tokenExpired'`, 不洩露 invalid/expired 之別, 詳 procCore 防 information leakage）, autoLogin 之 errTemp 被設值後於檢查階段清空 LS token 並以 `reject('token error')` 結束, App.vue 回登入頁。為防洩露「token 是否真實存在於 DB」, 依 spec 粒度規則本案例視覺終態與 E2E-004 等同, 共用同一張 baseline。
  - flow:
    - 測試資料：localStorage 寫入 DB 不存在之假 token 字串。
    - 操作：先到 baseUrl 設好假 token 至 localStorage → 再導向乾淨 baseUrl → App.vue mounted 自動觸發 autoLogin → checkToken reject → 外層 .catch 清空 localStorage token 後回登入頁。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上應出現 `Log in`（eng）/`登入`（cht）按鈕（已回登入頁）。
      2. 視覺：與 E2E-004 共用 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-004-no-token.png` 視覺一致（pixelmatch 容差）（防洩露 token 真偽, 視覺等同無 token 情境）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-008**
  - title: localStorage token 已過期回登入頁
  - description: 驗證 localStorage token 確實存在於 DB 但 `timeEnd` 已過期時, autoLogin 呼叫 checkToken, 後端因過期而 reject（對外統一回 key `'tokenExpired'`）, autoLogin 之 errTemp 被設值後清空 LS token 並以 `reject('token error')` 結束回登入頁。依 spec 粒度規則, 過期情境不顯示具體錯誤訊息以避免洩露 token 真偽, 視覺終態與 E2E-004 等同, 共用同一張 baseline。
  - flow:
    - 測試資料：user `id-autologin-ok` 之額外 token（`timeEnd` 為過去 60 分鐘的已過期 token）寫入 localStorage。
    - 操作：先到 baseUrl 設好已過期 token 至 localStorage → 再導向乾淨 baseUrl → App.vue mounted 自動觸發 autoLogin → checkToken 因過期 reject → 外層 .catch 清空 localStorage token 後回登入頁。
    - 驗證（等待 autoLogin 完成後）：
      1. 語意：DOM 上應出現 `Log in`（eng）/`登入`（cht）按鈕（已回登入頁）。
      2. 視覺：與 E2E-004 共用 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-004-no-token.png` 視覺一致（pixelmatch 容差）（防洩露 token 真偽, 視覺等同無 token 情境）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-009**
  - title: 非 admin 使用者 view=backstage 自動登入後僅見使用者資訊
  - description: 驗證非 admin 使用者（`isAdmin='n'`）之有效 token 已快取於 localStorage、且開啟登入頁時 URL 帶 `?view=backstage` 時，autoLogin 成功通過 token 驗證後停留於後台視圖，但因該使用者非系統管理員，前端 LayoutContent 之 isAdmin 過濾僅保留「使用者資訊」選單、隱藏統計資訊 / 使用者清單 / 金鑰清單 / IP清單 等管理員專屬選單，主內容區呈現使用者自身資訊頁。本案例與 E2E-002（admin 帶 view=backstage 看完整後台）構成「同為 view=backstage、admin vs 非 admin 之視圖權限分流」對照：非 admin 即使指定 backstage 亦無法看到任何管理功能。
  - flow:
    - 測試資料：user `id-autologin-ok`（非 admin / `isActive='y'` / `isAdmin='n'`）+ 其有效 token 寫入 localStorage。
    - 操作：於 localStorage 寫入該 user 之有效 token → 開啟登入頁並於網址帶 `?view=backstage` → 等待 autoLogin 自動完成。
    - 驗證（等待 autoLogin 完成、視圖渲染後）：
      1. 語意：側欄出現「User information」/「使用者資訊」（mmUserInfor 可見）；且**不**出現「Statistics information」/「統計資訊」（管理員專屬選單已被 LayoutContent isAdmin 過濾擋下）。
      2. 視覺：與 baseline `test/pics/autologin/autologin-{eng,cht}-E2E-009-ok-backstage-nonadmin.png` 視覺一致。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 token, 還原為 base seed。

- **E2E-010**
  - title: 後端 reject 統一由外層 catch 攔截回登入頁
  - description: 驗證 autoLogin 過程中任何後端 reject 或例外（包含 invalid token / duplicate tokens / token expired / invalid user 等）都統一被 core 之外層 .catch 接住, 通用錯誤 alert 已於程式碼註解不顯示, 僅以 reject 上拋原始 err 至 App.vue, 由 App.vue 統一將使用者帶回登入頁。本案例為一條「契約涵蓋宣告」, 其具體路徑分別由 E2E-006（user 停用）/ E2E-007（DB 查無 token）/ E2E-008（token 過期）三個案例分別驗證, 共同證實外層 catch 對所有 reject 路徑視覺終態統一回登入頁的契約。
  - flow:
    - 測試資料：不適用（本案例為「契約涵蓋宣告」，不獨立建測試資料）。
    - 操作：不適用。
    - 驗證：**無獨立 it()**；本契約由 E2E-006（帳號停用 reject）/ E2E-007（DB 查無 token reject）/ E2E-008（token 過期 reject）三案各自之「視覺終態統一回登入頁、共用 E2E-004 baseline」共同涵蓋，已證實 autoLogin 任一後端 reject 路徑皆由外層 catch 統一帶回登入頁。屬合法 gap（case 由其他案例涵蓋），不另建 case。
    - 雙語：不適用（無獨立截圖）。
    - 清理：不適用。

## i18n 訊息粒度規則

自動登入的 token / user 失效情境 (LS token 不存在 / token 已從 DB 移除 / token 過期 / user 已停用) **視覺終態統一為「靜默回到登入頁」**，不顯示具體錯誤訊息，避免洩露「token 是否真實存在於 DB」「user 是否被停用」等資訊給未驗證的瀏覽器端。

| 觸發情境 | i18n 鍵區位 (grep 提示) | 顯示位置 | 粒度規則 (spec) |
|---|---|---|---|
| 無 LS token | — | 無錯誤訊息 | **靜默**回登入頁 (`reject('no token')` 不觸發 alert) |
| LS token 存在但 DB 查無 (stale token) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，清空 LS token 後回登入頁 |
| token 在 DB 但已過期 (timeEnd < now) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，清空 LS token 後回登入頁 |
| user.isActive='n' (token 有效但 user 已停用) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，由外層 .catch 統一處理回登入頁 |
| webKey 尚未取得 | `server/procLang.mjs` 找 `failedLoginForNoWebKey` | 前端 alert / 錯誤訊息區 | 顯示 webKey 取得失敗的固定訊息 |
| autoLogin 成功但 user.redir 為空且 view=login | `server/procLang.mjs` 找 `failedLoginForNoRedir` | 前端 alert / 錯誤訊息區 | 顯示無有效轉址的固定訊息後回登入頁 (與一般登入流程共用同一鍵) |
| core 內未明確分類的例外 (外層 catch) | `server/procLang.mjs` 找 `failedLoginForCatch` (現行程式碼已註解，不主動顯示) | — | 通用錯誤 alert 已註解，**僅 reject('token error') / 原始 err 上拋給 App.vue**，由 App.vue 統一回登入頁，不顯示通用錯誤訊息 |

實際 i18n 鍵名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴後直接讀取，避免在本文件 mirror 翻譯字串造成 drift。

## 自動登入成功分流

| URL 條件 | useRedir | redir 欄位 | 結果 |
|---|---|---|---|
| 無 view 或 `view=login` | true | 有值 | 轉址至 redir 網址 (URL 自動 append `&lang=`) |
| 無 view 或 `view=login` | true | 無值 | 顯示無有效轉址錯誤 (見 i18n 訊息粒度規則表) 後回登入頁 |
| `view=backstage` | false | 不看 | 留在前端進入後台 |
| `view=user` | false | 不看 | 留在前端進入使用者資訊頁 |

## 參數來源

本流程涉及以下執行期參數，**讀取優先序：`settings.json` 覆寫值 > `server/WWebSso.mjs` 預設**：

| 概念 | 來源 (優先序) | 流程影響 |
|---|---|---|
| Token 有效期 (登入時建立的 timeEnd = now + N 分鐘) | `settings.json` 找 token 有效期相關 key → `server/WWebSso.mjs` opt 預設 | 影響自動登入可用窗口；寫測試時建有效 token 須讓 timeEnd 為未來、建過期 token 須讓 timeEnd 為過去 |
| localStorage 中 token key 前綴 (`<webKey>:userToken`) | `settings.json` 找 webKey | 影響 LS 讀寫鍵名；寫測試直接寫 LS 須對齊此 webKey |

實際數值 → 寫測試時讀 `settings.json` 對應 key，若無覆寫則查 `server/WWebSso.mjs` opt 預設。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：等 `syncState=true` → 取 `webKey` → 自 LS 取 `${webKey}:userToken` → 後端 `checkToken`（DB 存在 / 唯一 / 未過期）→ 後端 `getUserByToken`（含 `isActive:'y'`）→ user 物件回傳 → `useRedir` 分流。
- **粒度**：
  - token / user 失效情境（LS token 不存在 / DB 已移除 / 已過期 / user `isActive='n'`）**視覺終態統一為「靜默回登入頁」**，不顯示具體錯誤訊息（避免洩露「token 是否真實存在於 DB」「user 是否被停用」給未驗證的瀏覽器端）。
  - `webKey` 取得失敗 / `redir` 為空 各自具體訊息（為使用者操作前置條件，非 token 真偽相關）。
- **邊界**：
  - `checkToken` wrapper 永遠 reject 不 resolve(false)；三元運算 `errTemp ? 'token error' : 'token expired'` 實際**永遠走 'token error' 分支**，後者為防禦性 fallback。
  - `checkToken` 階段失敗（LS token 不存在於 DB / 已過期）時清空 LS token（避免 stale token 殘留）；其餘 reject 路徑（user 停用 / invalid user / invalid redir）由 `core` 外層 `.catch` 帶回登入頁但**不**清空 LS token。
  - `view=backstage` / `view=user` 不啟用 `useRedir`，自動登入成功後停留前端進入該功能頁。
- **契約**：
  - `syncState` 為 true 才執行（`waitFun` 無 timeout 等待，不 reject）。
  - 外層 `.catch` 接住所有 core 內未 catch 的 reject / throw，通用 alert 已註解；以 reject 回傳原始 err 給 `App.vue`，由 `App.vue` 統一回登入頁。
  - `goUrl` 自動 append `&lang=` 至 `redir` URL（語系跟著使用者跨應用）。
