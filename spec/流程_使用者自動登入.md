# 使用者自動登入流程

## 觸發

App.vue mounted 時自動執行。檢查 localStorage 是否有快取的 token，有則嘗試自動登入。

## 重要流程

> 編號規則:
> - `**E2E-NNN**`: UI baseline 測試, 對應 `test/e2e-autologin.test.mjs` + `test/pics/autologin/autologin-{lang}-E2E-NNN-*.png`
> - `**E2E-NNN(待補)**`: 編號預留, 尚無 e2e 待未來補

- **E2E-001** 使用者開登入網頁, 因過往已成功登入, 直接轉跳 redir
- **E2E-002** 使用者以 view=backstage 開啟頁面, 自動登入成功後停留 backstage (不轉址) (E2E-002-ok-backstage)
- **E2E-003** 使用者以 view=user 開啟頁面, 自動登入成功後停留 user view (不轉址) (E2E-003-ok-user)
- **E2E-004** 使用者開登入網頁, 因過往未登入, 直接轉回登入頁 (對應 no-token)
- **E2E-005** 使用者開登入網頁, 自動登入成功但使用者資料無 redir 欄位值, 顯示無有效轉址錯誤並轉回登入頁
- **E2E-006** 使用者開登入網頁, 過往已成功登入但帳號已非啟用 (isActive='n'), getUserByToken 查無使用者而 reject, 轉回登入頁 (共用 E2E-004 baseline, 視覺等同)
- **E2E-007** 使用者開登入網頁, token 快取存在但後端資料庫已查無 (如已登出或被管理員清除), 清空 localStorage token 並轉回登入頁 (共用 E2E-004 baseline)
- **E2E-008** 使用者開登入網頁, token 快取存在但已過期, 清空 localStorage token 並轉回登入頁 (共用 E2E-004 baseline)
- **E2E-009(不測試)** 使用者開登入網頁, 但前端 webKey 尚未取得, 顯示 webKey 取得失敗錯誤並轉回登入頁 (須在 SPA mount 前注入 store.webKey='', e2e 工具無穩定方式介入 autoLogin 觸發前的 store 狀態)
- **E2E-010** 自動登入過程中後端任何 reject/例外, 統一被外層 .catch 接住後以 reject 回傳 (alert 已註解, 不顯示通用錯誤訊息), 由 App.vue 轉回登入頁 (隱含 E2E-006/007/008: 各種具體 reject 路徑都走此外層 catch, 視覺終態統一回登入頁)

## 執行流程

```
001  從 URL 取得目標頁面 view，無參數預設 'login'  [App.vue:97]
002  呼叫 mUI.autoLogin，帶入是否轉址 (view==='login' 時啟用轉址)  [App.vue:101]
003      執行非同步流程 core()  [mUI.mjs:522]
004          等待 syncState 為 true (waitFun 無 timeout, 不會 reject)  [mUI.mjs:527]
005          從 store 取得 webKey 作為 $keyLS  [mUI.mjs:533]
006              無 $keyLS:
007                  顯示 webKey 取得失敗錯誤, reject('invalid $keyLS')  [mUI.mjs:541]
008          以 `${$keyLS}:userToken` 為 key, 從 localStorage 取得快取的 token  [mUI.mjs:554]
009              無 token:
010                  reject('no token')，靜默回到登入頁（不顯示錯誤）  [mUI.mjs:562]
011          呼叫後端 checkToken 驗證 token, 後端在過期或無效時一律 reject (永遠不 resolve(false))  [mUI.mjs:569]
012              查詢 token 是否存在於資料庫  [procCore.mjs:417]
013                  找不到:
014                      reject('invalid token')  [procCore.mjs:428]
015                  重複(>=2):
016                      reject('duplicate tokens')  [procCore.mjs:435]
017              比對到期時間 (tn < timeEnd)  [procCore.mjs:380]
018                  已過期:
019                      _checkToken 回傳 false; checkToken wrapper 將 false 轉為 reject('token expired')  [procCore.mjs:409, 485]
020              token 有效時 _checkToken 回傳 true; checkToken wrapper 也 return true  [procCore.mjs:456, 504]
021          .catch  [mUI.mjs:573]
022              後端任何 reject (invalid token / duplicate tokens / token expired) 都進這裡, 填入 errTemp  [mUI.mjs:573]
023          檢查 errTemp 或 b 為 false:
024              清空 localStorage token, reject('token error')  [mUI.mjs:582, 585]
025              註：因後端 wrapper 永遠 reject 不 resolve(false)，errTemp 必為 truthy，
                   三元運算 `errTemp ? 'token error' : 'token expired'` 永遠走 'token error' 分支；
                   'token expired' 分支為防禦性 fallback，現行程式碼路徑不會到達
026          呼叫後端 getUserByToken 取得使用者資訊，無 catch，reject 時 throw 至 .catch  [mUI.mjs:591]
027              以 token 查找 userId，再以 userId 查找使用者（_getGenUserByKV 查詢含 isActive:'y'）  [procCore.mjs:1147, 56]
028              回傳使用者物件（不含密碼）  [procCore.mjs:1251]
029          後端回傳成功，繼續前端處理  [mUI.mjs:591]
030          檢查回傳的使用者物件  [mUI.mjs:595]
031              無效:
032                  reject('invalid user')  [mUI.mjs:599]
033          更新前端狀態 (token + 使用者資訊)  [mUI.mjs:605]
034          檢查是否啟用轉址  [mUI.mjs:609]
035              useRedir=true 且有 redir:
036                  goUrl 帶當前 lang 自動 append &lang= 至 redir URL，轉址，resolve('redir')  [mUI.mjs:630]
037              useRedir=true 但無 redir:
038                  顯示無有效轉址錯誤，reject('invalid redir')  [mUI.mjs:620]
039              useRedir=false:
040                  登入完成，resolve('done')  [mUI.mjs:640]
041      .catch  [mUI.mjs:646]
042          接住 core 內所有未 catch 的 reject/throw  [mUI.mjs:646]
043          通用錯誤 alert 已註解, 不顯示給使用者  [mUI.mjs:650]
044          以 reject 回傳原始 err  [mUI.mjs:653]
045  .then  [App.vue:102]
046      前往 view 指定的功能頁，autoLogining = false  [App.vue:105]
047  .catch  [App.vue:110]
048      返回登入頁，autoLogining = false  [App.vue:113]
```

## i18n 訊息粒度規則

自動登入的 token / user 失效情境 (LS token 不存在 / token 已從 DB 移除 / token 過期 / user 已停用) **視覺終態統一為「靜默回到登入頁」**，不顯示具體錯誤訊息，避免洩露「token 是否真實存在於 DB」「user 是否被停用」等資訊給未驗證的瀏覽器端。

| 觸發情境 | i18n 鍵區位 (grep 提示) | 顯示位置 | 粒度規則 (spec) |
|---|---|---|---|
| 無 LS token | — | 無錯誤訊息 | **靜默**回登入頁 (`reject('no token')` 不觸發 alert) |
| LS token 存在但 DB 查無 (stale token) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，清空 LS token 後回登入頁 |
| token 在 DB 但已過期 (timeEnd < now) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，清空 LS token 後回登入頁 |
| user.isActive='n' (token 有效但 user 已停用) | — | 無錯誤訊息 | **與「無 LS token」視覺等同**，由外層 .catch 統一處理回登入頁 |
| webKey 尚未取得 | `server/procLang.mjs` 找 `failedLoginForNoWebKey` | 前端 alert / 錯誤訊息區 | 顯示 webKey 取得失敗的固定訊息 |
| autoLogin 成功但 user.redir 為空且 view=login | `server/procLang.mjs` 找 `failedLoginForNoRedir` | 前端 alert / 錯誤訊息區 | 顯示無有效轉址的固定訊息後回登入頁 (與一般登入流程共用同一鍵) |
| core 內未明確分類的例外 (外層 catch) | `server/procLang.mjs` 找 `failedLoginForCatch` (現行程式碼已註解，不主動顯示) | — | 通用錯誤 alert 已註解，**僅 reject('token error') / 原始 err 上拋給 App.vue**，由 App.vue 統一回登入頁，不顯示通用錯誤訊息 |

實際 i18n 鍵名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴後直接讀取，避免在本文件 mirror 翻譯字串造成 drift。

## 自動登入成功分流

| URL 條件 | useRedir | redir 欄位 | 結果 |
|---|---|---|---|
| 無 view 或 `view=login` | true | 有值 | 轉址至 redir 網址 (URL 自動 append `&lang=`) |
| 無 view 或 `view=login` | true | 無值 | 顯示無有效轉址錯誤 (見 i18n 訊息粒度規則表) 後回登入頁 |
| `view=backstage` | false | 不看 | 留在前端進入後台 |
| `view=user` | false | 不看 | 留在前端進入使用者資訊頁 |

## 參數來源

本流程涉及以下執行期參數，**讀取優先序：`settings.json` 覆寫值 > `server/WWebSso.mjs` 預設**：

| 概念 | 來源 (優先序) | 流程影響 |
|---|---|---|
| Token 有效期 (登入時建立的 timeEnd = now + N 分鐘) | `settings.json` 找 token 有效期相關 key → `server/WWebSso.mjs` opt 預設 | 影響自動登入可用窗口；寫測試時建有效 token 須讓 timeEnd 為未來、建過期 token 須讓 timeEnd 為過去 |
| localStorage 中 token key 前綴 (`<webKey>:userToken`) | `settings.json` 找 webKey | 影響 LS 讀寫鍵名；寫測試直接寫 LS 須對齊此 webKey |

實際數值 → 寫測試時讀 `settings.json` 對應 key，若無覆寫則查 `server/WWebSso.mjs` opt 預設。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：等 `syncState=true` → 取 `webKey` → 自 LS 取 `${webKey}:userToken` → 後端 `checkToken`（DB 存在 / 唯一 / 未過期）→ 後端 `getUserByToken`（含 `isActive:'y'`）→ user 物件回傳 → `useRedir` 分流。
- **粒度**：
  - token / user 失效情境（LS token 不存在 / DB 已移除 / 已過期 / user `isActive='n'`）**視覺終態統一為「靜默回登入頁」**，不顯示具體錯誤訊息（避免洩露「token 是否真實存在於 DB」「user 是否被停用」給未驗證的瀏覽器端）。
  - `webKey` 取得失敗 / `redir` 為空 各自具體訊息（為使用者操作前置條件，非 token 真偽相關）。
- **邊界**：
  - `checkToken` wrapper 永遠 reject 不 resolve(false)；三元運算 `errTemp ? 'token error' : 'token expired'` 實際**永遠走 'token error' 分支**，後者為防禦性 fallback。
  - 自動登入失敗一律清空 LS token（避免 stale token 殘留）。
  - `view=backstage` / `view=user` 不啟用 `useRedir`，自動登入成功後停留前端進入該功能頁。
- **契約**：
  - `syncState` 為 true 才執行（`waitFun` 無 timeout 等待，不 reject）。
  - 外層 `.catch` 接住所有 core 內未 catch 的 reject / throw，通用 alert 已註解；以 reject 回傳原始 err 給 `App.vue`，由 `App.vue` 統一回登入頁。
  - `goUrl` 自動 append `&lang=` 至 `redir` URL（語系跟著使用者跨應用）。
