# 使用者登出流程

## 觸發

使用者於登入後的功能頁點擊「登出 / Log out」：

- 後台（backstage，`viewState='backstage'`，Layout.vue）：點擊右上角 user popup，展開後點擊「Log out / 登出」。
- 使用者資訊頁（user，`viewState='user'`，PageUser.vue）：直接點擊「Log out / 登出」chip 按鈕。

兩入口最終皆透過 `vo.$ui.logout()` 走同一條登出流程。

- **E2E-003**
  - title: 後端登出 reject 仍正常清空 LS 回登入頁
  - description: 驗證一般使用者於使用者資訊頁點擊「Log out / 登出」時，若後端 `logoutByToken` 因網路或 DB 錯誤而 reject，前端 `mUI.logout` core 內以 `.catch(() => {})` 靜默屏蔽錯誤、不顯示給使用者，仍續走「LS token 清為空字串 + viewState 切回 'login'」，確保使用者能正常離開。本案例為登出流程之容錯契約，spec 規定後端 reject 不阻擋前端清空 LS。

## i18n 訊息粒度規則

登出流程的「成功路徑」**無顯示訊息**（直接切 viewState 回登入頁，使用者觀察到的就是畫面切回登入畫面）。錯誤路徑也只在 webKey 失敗、core 非預期例外兩種前置情境顯示，後端 logoutByToken 的 reject 一律被 `.catch(() => {})` 屏蔽。

| 觸發情境 | i18n 鍵區位 (grep 提示) | 顯示位置 | 粒度規則 (spec) |
|---|---|---|---|
| webKey 尚未取得 | `server/procLang.mjs` 找 `failedLogoutForNoWebKey` | 前端 alert | 顯示 webKey 取得失敗的固定訊息, 不繼續清空 LS |
| core 內非預期例外（webKey 失敗以外） | `server/procLang.mjs` 找 `failedLogoutForCatch` | 前端 alert | 顯示通用「無法登出」訊息, 不洩露具體原因 |
| 後端 logoutByToken reject（invalid token / duplicate tokens / failed to delete / can not delete） | — | 無錯誤訊息 | **靜默屏蔽**（`.catch(() => {})`），避免斷線或 token 已不存在時無限報錯，仍續走清空 LS + 回登入頁 |
| 登出成功 | — | 無錯誤訊息 | 畫面直接切回登入頁；登出文字按鈕本身 i18n 鍵見 `server/procLang.mjs` 找 `logout` |
| 連線狀態列「已登出」顯示文字 | `server/procLang.mjs` 找 `csLogout` | LayoutState.vue 連線狀態區 | 連線層的視覺終態文字，與本登出流程的 viewState 切換不同步驅動，僅作為 connState 顯示參照 |

實際 i18n 鍵名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴後直接讀取，避免在本文件 mirror 翻譯字串造成 drift。

## LocalStorage Token 清空慣例

登出後 LS token 設定方式為 `localStorage.setItem(key, '')` 將值設為空字串，**非** `removeItem(key)`。差別：

- `setItem('', '')`：key 仍存在於 LS，`getItem(key)` 回傳 `''`。
- `removeItem(key)`：key 由 LS 移除，`getItem(key)` 回傳 `null`。

兩者對「自動登入是否被攔下」的效果一致（自動登入流程於 `mUI.autoLogin` 步驟 008-009 以 `isestr(token)` 判定，空字串與 null 皆為 falsy 而 reject('no token')），但寫測試斷言時須對齊實際 setItem 行為（assert LS token 為 `''` 而非 `null`）。

## 參數來源

本流程涉及以下執行期參數，**讀取優先序：`settings.json` 覆寫值 > `server/WWebSso.mjs` 預設**：

| 概念 | 來源 (優先序) | 流程影響 |
|---|---|---|
| localStorage 中 token key 前綴 (`<webKey>:userToken`) | `settings.json` 找 webKey | 影響 LS 讀寫鍵名；寫測試直接驗 LS 須對齊此 webKey |

登出流程本身不直接消費 token 有效期、登入失敗閾值等參數（這些屬於登入 / 自動登入 / 自動封鎖流程的範疇）。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：取 `webKey` → 自 LS 取 `${webKey}:userToken` → 後端 `logoutByToken`（DB 存在 / 唯一 → 刪除）→ LS token 清空為 `''` → 前端 `updateViewState('login')` 切回登入頁。
- **粒度**：
  - 登出成功路徑**無顯示訊息**，使用者觀察的終態為「畫面回登入頁」。
  - 後端 logoutByToken 任何 reject 一律**靜默屏蔽**（`.catch(() => {})`），不顯示給使用者，避免斷線或 token 已不存在的場景下無限報錯。
  - 前置條件失敗（webKey 取得失敗 / core 非預期例外）各自具體 alert 訊息（為使用者操作前置條件，非 token 真偽相關）。
- **邊界**：
  - LS token 清空採 `setItem(key, '')` 設為空字串，**非** `removeItem`；寫測試斷言 LS 為 `''`。
  - 後端 logoutByToken 不經 procProtect 保護層，由 core 直接執行；前端 $fapi 走 `/api/logoutByToken` 端點（WWebSso.mjs:843），該端點先呼叫 `pp.callApiByToken` 計入頻率再執行核心邏輯。
  - 後端 logoutByToken reject 不阻擋前端清空 LS：即使後端刪除失敗，前端仍續走 LS 清空 + viewState 切換，確保使用者能離開。
  - viewState 切換由 `mUI.logout().then` 內呼叫 `updateViewState('login')` 完成，**非** logout 函式內部自動切；故 logout 的 .then 處理（Layout.vue / PageUser.vue）為「成功登出 → 切回登入頁」的必要環節。
- **契約**：
  - 登出後 `localStorage.getItem('${webKey}:userToken')` 必為 `''`（空字串），下次開啟頁面時自動登入流程以 `isestr(token)` 判 falsy 後 reject('no token') 靜默回登入頁，**不會** autoLogin 復原。
  - 後端 logoutByToken 成功刪除 token 後寫 `srLog.info({ event: 'fun-logout', token, userId })`。
  - 兩入口（Layout user popup / PageUser chip）共用同一條 `vo.$ui.logout()` 邏輯，僅 UI 觸發位置不同；spec 對兩入口行為要求一致。
