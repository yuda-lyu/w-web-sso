# 使用者創建帳密流程

## 觸發

使用者在 PageLogin.vue 點擊「Register」進入註冊表單，填寫完成後點擊「Submit」。

## 重要流程

> 編號規則:
> - `**E2E-NNN**`: UI baseline 測試, 對應 `test/e2e-register.test.mjs` + `test/pics/register/register-{lang}-E2E-NNN-*.png`
> - `**E2E-NNN(it-only)**`: 有 it() 案例 (含 dialog text 斷言) 但無 baseline
> - `**E2E-NNN(待補)**`: 編號預留, 尚無 e2e 待未來補

- **E2E-001** 使用者於登入頁點擊「Register」link, viewMode 由 'login' 切換至 'register' (PageLogin input 數從 2 增至 5: account / password / confirmPassword / name / email), 顯示註冊表單
- **E2E-002** 使用者於登入頁點擊註冊, 密碼過短跳 inline 紅字 (E2E-002-pw-too-short)
- **E2E-003** 使用者於登入頁點擊註冊, 密碼與確認密碼不同跳 inline 紅字 (E2E-003-pw-mismatch)
- **E2E-004** 使用者於登入頁點擊註冊, 密碼觸發多項策略違反跳多條 inline 紅字 (E2E-004-pw-multi-errors)
- **E2E-005** 使用者於登入頁點擊註冊, 檢測ooo都成功, 註冊成功並將表單清空回 login mode (E2E-005-success)
- **E2E-006** 使用者收信點驗證連結, 驗證成功頁 (E2E-006-verify-success)
- **E2E-007** 使用者點擊驗證信連結, token 不存在或已被使用, 顯示 server-rendered 失敗頁（依 ?lang= 渲染對應語系訊息）(E2E-007-verify-invalid)
- **E2E-008** 使用者點擊驗證信連結, 帳號已驗證過, 顯示 server-rendered 已驗證頁（依 ?lang= 渲染對應語系訊息）(E2E-008-verify-already)
- **E2E-009** 使用者於註冊表單點擊「Back to login」link, viewMode 由 'register' 切換回 'login' (PageLogin input 數從 5 回到 2), 視為取消註冊逃生口（不送出資料、不清空已輸入內容）(E2E-009-back-to-login)
- **E2E-010** 使用者於登入頁點擊註冊, 檢測未給予帳號, 無法註冊 (Submit 灰態無法觸發) (E2E-010-account-empty)
- **E2E-011** 使用者於登入頁點擊註冊, 檢測未給予密碼, 無法註冊 (Submit 灰態無法觸發) (E2E-011-password-empty)
- **E2E-012** 使用者於登入頁點擊註冊, 檢測未給予email, 無法註冊 (Submit 灰態無法觸發) (E2E-012-email-empty)
- **E2E-013** 使用者於登入頁點擊註冊, 檢測ooo未給予姓名, 無法註冊 (Submit 灰態無法觸發) (E2E-013-name-empty)
- **E2E-014(it-only)** 使用者於登入頁點擊註冊, 檢測ooo email格式不合, 無法註冊 (後端 reject alert, 用 dialog text 斷言)
- **E2E-015(it-only)** 使用者於登入頁點擊註冊, 檢測ooo帳號已被註冊, 無法註冊 (後端 reject alert, 用 dialog text 斷言)
- **E2E-016(it-only)** 使用者於登入頁點擊註冊, 檢測ooo email已被註冊, 無法註冊 (後端 reject alert, 用 dialog text 斷言)
- **E2E-017(不測試)** 使用者於登入頁點擊註冊, 系統不允許自助註冊, 無法註冊 (需改 settings.json allowUserRegistration + 重啟 server, 不在自動測試 cost 範圍)
- **E2E-018** 使用者於登入頁點擊註冊, 檢測ooo都成功但寄驗證信失敗, 仍完成註冊但使用者收不到驗證信, 須透過重寄機制 (隱含 E2E-005: 測試環境 SMTP 即為 placeholder pw, E2E-005-success 已涵蓋 SMTP fail 仍成功註冊路徑)
- **E2E-019** 使用者點擊驗證信連結, token 非驗證用途, 對 users 表查詢落空, 顯示 server-rendered 失敗結果頁（依 ?lang= 渲染對應語系訊息）(隱含 E2E-007: 後端 users.tokenVerify 查無與 'token 不存在' 共用同訊息與 server-rendered 頁)
- **E2E-020** 使用者於未驗證提示點擊重寄, 檢測 email 與帳號不符, 無法重寄 (E2E-020-resend-email-mismatch, 顯示 inline resendError 紅字)
- **E2E-021** 使用者於未驗證提示點擊重寄, 寄信失敗, 無法重寄 (隱含 E2E-020: SMTP 失敗 reject 'send email failed', 同 inline 位置顯示 userRegistrationResendFailed 訊息, UI 結構同 E2E-020)

```
021      讀取 server/template/verifyEmailResult.html，
           以 lang 從 kpLang 取出 webName 與對應訊息文字，代入 {title}/{message}  [WWebSso.mjs:1046-1058]
022      直接 res.response(html).type('text/html; charset=utf-8') 回吐 HTML 結果頁  [WWebSso.mjs:1060]
```

> **架構備註**：驗證結果頁為 server-rendered HTML（白底簡潔），**不再 redirect 回 SPA 顯示彈窗**。
> - lang 端到端跟著驗證流程走（寄信時帶 ?lang=、API 收到後直接渲染對應語系），不依賴 SPA reload 後重新求 lang
> - 同時消除「任何人在網址列打 ?verified=ok 都會看到假驗證成功訊息」的 UX 缺陷
> - 使用者驗證後須自行回到登入頁登入（驗證連結可能在不同裝置開啟，無 auto-redirect 反而合理）

### 五、新帳號狀態變化

| 階段 | timeVerified | tokenVerify | isAdmin | 可登入 |
|---|---|---|---|---|
| 剛自助註冊（自助）| 空 | 隨機字串 | 'n' | 否 |
| 後台直接建帳（管理員後台）| 自動填入 now | 不產生 | 可設定 | 是 |
| 點擊驗證連結後 | 填入時間 + 清空 tokenVerify | 空 | 不變 | 是 |
| 正常登入 | 有值 | 空 | 不變 | 是 |

自助註冊與後台建帳的差異彙整：

| 項目 | 自助註冊 | 後台建帳 |
|---|---|---|
| `timeVerified` | 空（須驗證）| 自動填入 now（視為已驗證）|
| `isAdmin` | 強制 'n' | 可由管理員指定 |
| 驗證信 | 自動寄出 | 不寄 |
| `tokenVerify` | 產生隨機字串存於 `users.tokenVerify` | 不產生 |
| 觸發來源 | `procCore.createUser`（自助）| 後台 Users list CRUD |

## 參數來源

本流程涉及以下執行期參數，**測試讀取順序：`settings.json` 覆寫值 > `server/WWebSso.mjs` opt 預設**：

| 概念 | 來源（優先序）| 測試影響 |
|---|---|---|
| 是否允許自助註冊 | `settings.json` `allowUserRegistration` → opt 預設 | 構造「系統不允許註冊」case 須設 false |
| 密碼策略（長度上下限 / 字元類要求 / 禁用字元 / 共用黑名單 / 與帳號連續字元門檻）| `settings.json` `passwordPolicy` → opt 預設 | 構造「密碼太短」case 須長度 < `minLength`；「黑名單」case 須挑 `commonPasswordBlacklist` 內值；「與帳號連續字元」case 須讓密碼與 account 有 ≥ `consecutiveCharsMinMatch` 字元連續子字串 |
| Email regex 格式 | hardcode `server/procCore.mjs` `createUser` 內 | 構造 invalid email 用無 `@` / 無 domain 字串 |
| 驗證信連結 base URL | `server/WWebSso.mjs` 計算為 `http://localhost:{serverPort}` | 測試環境連結 host 須對應 |
| 驗證信寄出 SMTP | `settings.json` `emSrc*` 系列 | SMTP 不通會等網路 timeout（測試須給寬鬆 timeout，~30s）|
| 鹽 salt | `settings.json` `salt` → opt 預設 | 比對 DB password hash 須用同 salt |
| Token 有效期 | `settings.json` `minExpired` → opt 預設 | 影響註冊後 login token / 驗證後 session 行為 |

實際數字 / 字元集 → 寫測試時讀 `settings.json` 對應 key，若無 → 讀 `server/WWebSso.mjs` opt 預設值。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**（註冊）：`allowUserRegistration` → account 非空 → email regex → 密碼 / 確認密碼一致 → `checkUserPassword` 策略 → name 非空 → 全表查唯一性（account / email）→ hash + 產生 tokenVerify → 寫入 users 表 → 寄驗證信。
- **驗證順序**（驗證信）：token 非空 → 對 `users.tokenVerify` 欄位查找對應使用者 → `timeVerified` 為空 → 寫入 `timeVerified=now` + 清空 `tokenVerify` → 渲染 server HTML 結果頁。
- **驗證順序**（重寄）：account / email 非空 → 查找 user → email 與帳號一致 → 未驗證 → 產生新 `tokenVerify` 覆寫 → 寄驗證信。
- **粒度**：
  - 註冊欄位驗證錯誤帶具體訊息（使用者已自填欄位，無列舉風險）。
  - 密碼策略違反帶**具體策略名**。
  - 重寄時帳號不存在 / email 與帳號不符 **共用同一訊息「invalid account or email」**（防帳號列舉）；已驗證 / 寄信失敗 各自具體訊息。
- **邊界**：
  - 寄驗證信失敗**不阻擋註冊**（使用者可透過重寄機制補救）。
  - `tokenVerify` 存於 `users.tokenVerify` 欄位，**非獨立 tokens 表**；故無「刪除舊驗證 token」步驟，直接 overwrite 即視為失效。
  - 驗證結果頁為 **server-rendered HTML**（不 redirect 回 SPA），消除「網址列打 ?verified=ok 顯示假驗證」缺陷。
  - 自助註冊強制 `isAdmin='n'`、`timeVerified=''`、需驗證；後台建帳可指定 `isAdmin`、`timeVerified=now`、不寄驗證信。
- **契約**：
  - 驗證連結含 `?lang=` 參數，端到端不依賴 SPA reload 重新求 lang。
  - 自助 vs 後台建帳的狀態差異詳「執行流程 → 五、新帳號狀態變化」表。
  - 重寄驗證信 overwrite `tokenVerify`，舊連結立即失效（後端查 `tokenVerify` 落空 → reject 'verifyEmailInvalidToken'）。
  - password 加鹽雜湊後寫入；驗證信標題由 i18n key 控制、body 由 `server/template/regVerifyEmail-{eng,cht}.html` 控制。
