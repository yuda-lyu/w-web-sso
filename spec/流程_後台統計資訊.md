# 後台統計資訊流程

## 觸發

管理員登入後台後，左側導覽預設停在「Statistics information」（後台統計資訊頁，`LayoutContentStaInfor.vue`）。此頁聚合呈現使用者 / 金鑰 / IP 三大面向之計數卡片、頻率圖表（登入 / 金鑰 / IP）與管控狀態卡片，提供管理員一頁綜覽系統運行狀況。

後端 `getStaUserSummary` / `getStaTokenSummary` / `getStaIpSummary` / `getStaUserAccountLogin` / `getStaToken` / `getStaIp` 共 6 個 RPC 皆以 `funCheckAdmin` 包裝（`server/WWebSso.mjs:1412,1419,1426,1433,1440,1448`），**僅具 admin 權限的有效 token 可存取**；token 無效／過期／非 admin 一律 reject。

## 重要流程

- **E2E-001**
  - title: 管理員進入統計資訊頁顯示初始檢視態
  - description: 驗證管理員以有效 admin token 登入後台後進入「Statistics information」頁，前端 mounted 階段呼叫 `getAndRelaData` 並行呼叫 6 個 `getSta*` API，後端各自回傳統計結果，前端依序綁定至使用者區（total/active/locked/expired）、管控區（active/created24h/ending24h/ended/conn24h/blocked）卡片與三個頻率圖表（freqLogin/freqToken/freqIp）。本案例為此流程之入口檢視，後續失敗案例皆以此為對照基準。屬正常成功路徑案例。
  - flow:
    - 測試資料：admin user（帳號 `stainfor-admin` / 密碼 `Pw@stainfor1` / `isActive='y'` / `isAdmin='y'` / `timeVerified` 有值 / `redir` 帶 `?view=backstage&token={token}`）+ 有效 admin token（timeEnd 為 60 分鐘後）+ base seed（3 users + 4 tokens + 0 ips）。
    - 操作：開乾淨登入頁（localStorage 無 token）→ 輸入帳號與密碼 → 點「Log in」/「登入」按鈕 → 跳 backstage 預設停在 Statistics 頁 → 等所有 `getSta*` API 回完。
    - 驗證：
      1. 語意（DOM 文字）：頁面含「Statistics information」/「統計資訊」標題 + 使用者資訊區「Total Users」/「總使用者」標籤 + 管控狀態區「Active tokens」/「有效金鑰數量」標籤。
      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-001-page-loaded.png` byte-equal。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 admin token，保留 base seed。

- **E2E-002**
  - title: 管理員 token 失效時頁面顯示載入失敗訊息
  - description: 驗證管理員以有效 admin token 登入後台進入 Statistics 頁後，若 token 過期失效，再次回到 Statistics 頁時（元件 unmount 後 remount，重新觸發 mounted hook），`getAndRelaData` 以 `Promise.allSettled` 並行 6 個 `getSta*` API，因 token 驗證失敗全數 reject；`Promise.allSettled` 等全部 settle 後 rejected 任一即 throw，mounted 外層 `.catch` 設 `errMsg=$t('getDataError')`，`.finally` 設 `firstLoading=false`。template `v-if="!firstLoading && !errMsg"` 為 false → 主內容（卡片 + 圖表 + 表格）隱藏，進入 `v-else` 之 `v-if="errMsg"` 顯示 `getDataError` 訊息（eng「Failed to get data, please try again later」/ cht「取得數據失敗，請稍後再試」）。屬非正常路徑案例，與 E2E-001 形成「有效 token 顯示主內容 / 失效 token 顯示錯誤訊息」之對照。
  - flow:
    - 測試資料：admin user（帳號 `stainfor-admin` / 密碼 `Pw@stainfor1` / `isActive='y'` / `isAdmin='y'` / `timeVerified` 有值 / `redir` 帶 `?view=backstage&token={token}`）+ admin token（初始 timeEnd 為 60 分鐘後，將於進入 Statistics 第二輪前由後端強制改為 1 分鐘前過期）+ base seed（3 users + 4 tokens + 0 ips）。
    - 操作：開乾淨登入頁（localStorage 無 token）→ 輸入帳號與密碼 → 點「Log in」/「登入」按鈕 → 跳 backstage 預設停在 Statistics 頁 → 切到「Users」/「使用者清單」（觸發 Statistics 元件 unmount）→ 後端強制將該 admin token 之 `timeEnd` 改為 1 分鐘前 → 點「Statistics information」/「統計資訊」回到 Statistics 頁（元件 remount，mounted hook 重新觸發 `getAndRelaData`，`Promise.allSettled` 並行 6 個 `getSta*` 全因 token 過期 reject → throw 至 mounted 外層 `.catch` 設 `errMsg`，`.finally` 設 `firstLoading=false`）→ 等錯誤訊息渲染完成。
    - 驗證：
      1. 語意（DOM 文字）：頁面顯示 `getDataError` 對應文字（eng「Failed to get data, please try again later」/ cht「取得數據失敗，請稍後再試」），且主內容區域之卡片標籤（如「Total Users」/「總使用者」）不再出現於 DOM（主內容被 `v-if="!firstLoading && !errMsg"` 隱藏）。
      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-002-admin-token-expired-page-empty.png` byte-equal（主代理將重產，預期僅見 page header + 錯誤訊息文字，無卡片區塊）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 user 與 admin token，保留 base seed。

## 參數來源

| 概念 | 來源 | 流程影響 |
|---|---|---|
| 操作者 token | 前端 store（登入後 admin token） | 後端以 `funCheckAdmin` 驗證；失效則所有 `getSta*` reject，前端 reactive 變數維持初始空值 |
| 統計時間範圍 | 後端 `procStaInfor` 內部固定（最近 7 天 + 各時間粒度 1hr/4hr/8hr/1day） | 與請求時間相對；本檔之 seed `timeCreate` 設為 2025-01-01（>1 年前），三個頻率圖表均落在 7 天視窗外 → 圖表渲染空資料 |

## spec 規則摘要

- **權限**：6 個 `getSta*` 皆 admin-only（`funCheckAdmin`）。
- **粒度**：本頁為純顯示（無修改 / 刪除 / 儲存）。不會觸發 `showCheckYes` modal 或 `$alert` toast。
- **邊界**：頁面交互元素（時間粒度選擇 / 個別顯示 checkbox / 顯示全部連結）僅影響前端圖表渲染樣式，不會重新呼叫後端 API；故本流程不涵蓋此類 UI 互動之 e2e。
- **契約**：mounted 時 `getAndRelaData` 用 `Promise.allSettled` 並行 6 個 `getSta*`，任一 reject 即向上 propagate 至 mounted 外層 `.catch` 設 `errMsg=$t('getDataError')`；mounted 外層 `.finally` 設 `firstLoading=false`；6 個 `grStaXxx` 內部 `.catch` 各自 `console.log` 後 `throw err` 讓錯誤可向上 propagate。template `v-if="!firstLoading && !errMsg"` 為 true 才顯示主內容（卡片 + 圖表 + 表格），否則進入 `v-else` 依 `firstLoading` / `errMsg` 顯示等待或錯誤文字。對齊 `LayoutContentUserInfor` canonical pattern。
- **截圖範圍取捨**：E2E-001 的 byte-equal baseline 僅截上方 cards 區（y:0..330），刻意排除下方三個頻率圖表。理由：圖表呈現「最近 7 天」資料且依登入活動 bucket 化（1hr 預設粒度），spike 位置會隨測試執行的小時 bucket 變動，跨時間 byte-equal 不穩；而 cards 區（Total Users / Active Users / Blocked Users / Expired Users）僅依賴 DB seed 計數（與 wall-clock 無關），可確定性穩定。圖表本身之渲染正確性屬於 ECharts 套件邊界，不適合用 pixel byte-equal 守護，本流程不涵蓋。E2E-002 之 `errMsg` 顯示路徑亦適用同一 clip（y:0..330）：錯誤訊息 div 位於 `v-else` 內、`padding:10px 15px`、`font-size:0.8rem`，渲染於 page header 之下（約 y=60-100），落在 0..330 範圍內可完整涵蓋；同時主內容被 `v-if="!firstLoading && !errMsg"` 隱藏，clip 範圍內亦無圖表干擾。
