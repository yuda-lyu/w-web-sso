# 後台統計資訊流程

## 觸發

管理員登入後台後，左側導覽預設停在「Statistics information」（後台統計資訊頁，`LayoutContentStaInfor.vue`）。此頁聚合呈現使用者 / 金鑰 / IP 三大面向之計數卡片、頻率圖表（登入 / 金鑰 / IP）與管控狀態卡片，提供管理員一頁綜覽系統運行狀況。

後端 `getStaUserSummary` / `getStaTokenSummary` / `getStaIpSummary` / `getStaUserAccountLogin` / `getStaToken` / `getStaIp` 共 6 個 RPC 皆以 `funCheckAdmin` 包裝（`server/WWebSso.mjs:1266,1260,1269,1278,1287,1296`；`funCheckAdmin` 定義於 `server/WWebSso.mjs:541`），**僅具 admin 權限的有效 token 可存取**；token 無效／過期／非 admin 一律 reject。

## 重要流程

- **E2E-001**
  - title: 管理員進入統計資訊頁顯示初始檢視態
  - description: 驗證管理員以有效 admin token 登入後台後進入「Statistics information」頁，前端 mounted 階段呼叫 `getAndRelaData` 並行呼叫 6 個 `getSta*` API，後端各自回傳統計結果，前端依序綁定至使用者區（total/active/locked/expired）、管控區（active/created24h/ending24h/ended/conn24h/blocked）卡片與三個頻率圖表（freqLogin/freqToken/freqIp）。本案例為此流程之入口檢視，後續失敗案例皆以此為對照基準。屬正常成功路徑案例。

    - 測試資料：admin user（帳號 `stainfor-admin` / 密碼 `Pw@stainfor1` / `isActive='y'` / `isAdmin='y'` / `timeVerified` 有值 / `redir` 帶 `?view=backstage&token={token}`）+ 有效 admin token（timeEnd 為 60 分鐘後）+ base seed（3 users + 4 tokens + 0 ips）。

      2. 視覺：與 baseline `test/pics/stainfor/stainfor-{eng,cht}-E2E-001-page-loaded.png` 視覺一致（pixelmatch 容差）。

- **E2E-002**
  - title: 管理員 token 失效時頁面顯示載入失敗訊息
  - description: 驗證管理員以有效 admin token 登入後台進入 Statistics 頁後，若 token 過期失效，再次回到 Statistics 頁時（元件 unmount 後 remount，重新觸發 mounted hook），`getAndRelaData` 以 `Promise.allSettled` 並行 6 個 `getSta*` API，因 token 驗證失敗全數 reject；`Promise.allSettled` 等全部 settle 後 rejected 任一即 throw，mounted 外層 `.catch` 設 `errMsg=$t('getDataError')`，`.finally` 設 `firstLoading=false`。template `v-if="!firstLoading && !errMsg"` 為 false → 主內容（卡片 + 圖表 + 表格）隱藏，進入 `v-else` 之 `v-if="errMsg"` 顯示 `getDataError` 訊息（eng「Failed to get data, please try again later」/ cht「取得數據失敗，請稍後再試」）。屬非正常路徑案例，與 E2E-001 形成「有效 token 顯示主內容 / 失效 token 顯示錯誤訊息」之對照。

## 參數來源

| 概念 | 來源 | 流程影響 |
|---|---|---|
| 操作者 token | 前端 store（登入後 admin token） | 後端以 `funCheckAdmin` 驗證；失效則所有 `getSta*` reject，前端 reactive 變數維持初始空值 |

## spec 規則摘要

- **權限**：6 個 `getSta*` 皆 admin-only（`funCheckAdmin`）。
- **粒度**：本頁為純顯示（無修改 / 刪除 / 儲存）。不會觸發 `showCheckYes` modal 或 `$alert` toast。
- **邊界**：頁面交互元素（時間粒度選擇 / 個別顯示 checkbox / 顯示全部連結）僅影響前端圖表渲染樣式，不會重新呼叫後端 API；故本流程不涵蓋此類 UI 互動之 e2e。
- **契約**：mounted 時 `getAndRelaData` 用 `Promise.allSettled` 並行 6 個 `getSta*`，任一 reject 即向上 propagate 至 mounted 外層 `.catch` 設 `errMsg=$t('getDataError')`；mounted 外層 `.finally` 設 `firstLoading=false`；6 個 `grStaXxx` 內部 `.catch` 各自 `console.log` 後 `throw err` 讓錯誤可向上 propagate。template `v-if="!firstLoading && !errMsg"` 為 true 才顯示主內容（卡片 + 圖表 + 表格），否則進入 `v-else` 依 `firstLoading` / `errMsg` 顯示等待或錯誤文字。對齊 `LayoutContentUserInfor` canonical pattern。
- **截圖範圍取捨**：E2E-001 的 視覺一致（pixelmatch 容差） baseline 僅截上方 cards 區（y:0..330），刻意排除下方三個頻率圖表。理由：圖表呈現「最近 7 天」資料且依登入活動 bucket 化（1hr 預設粒度），spike 位置會隨測試執行的小時 bucket 變動，跨時間 視覺一致（pixelmatch 容差） 不穩；而 cards 區（Total Users / Active Users / Blocked Users / Expired Users）僅依賴 DB seed 計數（與 wall-clock 無關），可確定性穩定。下方三個頻率圖表與兩個用量表(展示功能)之呈現另由 **E2E-003~007** 各自獨立涵蓋(每項捲到置中、紅框聚焦單一圖/表)：因圖表為動態 canvas(跨進程 GPU 渲染漂移)、且圖表 X 軸與表格「近 N 時」皆為 wall-clock 時間窗會位移, 無法直接 pixel 守護, 故該五案視覺以「預存真實快照貼圖覆蓋」穩定化(兩端貼同一快照, 呈現真實圖/表而非遮黑), 語意層讀 live DOM 驗結構(標題/表頭/有資料列), 不驗會飄的計數值。E2E-001 仍維持僅截 cards 區(確定性穩定)之取捨。E2E-002 之 `errMsg` 顯示路徑亦適用同一 clip（y:0..330）：錯誤訊息 div 位於 `v-else` 內、`padding:10px 15px`、`font-size:0.8rem`，渲染於 page header 之下（約 y=60-100），落在 0..330 範圍內可完整涵蓋；同時主內容被 `v-if="!firstLoading && !errMsg"` 隱藏，clip 範圍內亦無圖表干擾。
