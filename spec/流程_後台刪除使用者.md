# 後台刪除使用者流程

## 觸發

管理員於 LayoutContentUsers.vue 後台 Users list 勾選一列以上, 點「刪除勾選使用者」垃圾桶按鈕將該批列從前端 rows 過濾, 再點「儲存」批次提交至後端執行 procOrm del.

## 重要流程

> 編號規則:
> - `**E2E-NNN**`: UI baseline 測試, 對應 `test/e2e-deleteuser.test.mjs` + `test/pics/deleteuser/deleteuser-{lang}-E2E-NNN-*.png`
> - `**API-NNN**`: 後端契約測試, 對應 `test/api-deleteuser.test.mjs`

- **E2E-001** 勾選後點刪除, 起始 Users list (delete-success 步驟 1: 001-initial-users-list)
- **E2E-002** 勾選後點刪除, 點 trash 後 pending save (delete-success 步驟 2: 002-after-trash-pending-save)
- **E2E-003** 勾選後點刪除, 點 save 後 success modal (delete-success 步驟 3: 003-modal-delete-success)
- **E2E-004** 勾選後點刪除, refetch 後 target 永刪 (delete-success 步驟 4: 004-after-refetch-target-deleted)
- **E2E-005** 管理員勾選後點刪除, 但勾全選導致 rows 整張表為空, 前端以 CheckYes modal 顯示對應訊息後不送出
- **E2E-006** 管理員勾選包含自己列點刪除後儲存, 自己 row 已從 rows 移除, 前端以 CheckYes modal 顯示「不可刪除自己」之語系化訊息並不送出（後端為第二道防線同條訊息 reject）
- **E2E-007** 管理員勾選後點刪除, 點儲存時 token 已過期 / 已被刪, 後端 reject, 前端以 CheckYes modal 顯示「儲存失敗」訊息（userSaveUsersFail 前綴 + 後端 err）
- **API-001** 管理員以非 admin token 呼叫 updateUsersList API, 後端 funCheckAdmin 判否, 與「真過期」共用同一 reject 訊息（不洩露身分檢查細節）(`non-admin-token-reject` mocha case 僅 API 斷言, 無 baseline)

## 執行流程

### 一、勾選列（rowChecked）

```
001  管理員於 ag-grid 列首 checkbox 勾選一列以上 (僅 isEditable 顯示 checkbox)
002  WAggridVue rowChecked 回呼觸發  [LayoutContentUsers.vue:1107]
003  vo.itemsCheck = cloneDeep(rs)
        rs 為 ag-grid 回傳之勾選列陣列, 元素含 data.id (用於後續比對)
004  hasItemsCheck = size(vo.itemsCheck) > 0 = true → 垃圾桶按鈕浮現
        (按鈕顯示條件: isEditable && hasItemsCheck)
```

### 二、刪除（deleteItemsCheck）

```
001  管理員點垃圾桶按鈕「刪除勾選使用者」  [LayoutContentUsers.vue:160]
002  size(vo.itemsCheck) === 0 守門 → 為 0 顯示對應錯誤訊息即 return
        (正常 UI 流程下, hasItemsCheck=false 時按鈕不顯示, 此分支為防呆)
003  rows = get(vo, 'opt.rows', []) → cloneDeep(rows)
004  逐一掃描 vo.itemsCheck:
        id = get(v, 'data.id', '')
        若 id 非有效字串 → continue (跳過)
        rows = filter(rows, (vv) => vv.id !== id)   //從 rows 移除該 id
005  vo.itemsCheck = []   //勾選清空 (rows 內已不含這些列, ag-grid 也不會再回傳這些 row)
006  vo.users = cloneDeep(rows) → 連帶驅動 computed 重算 items / opt.rows, 表格立即少列
007  isModified = true → 顯示紅底「儲存」按鈕
        注意: 此階段未呼叫任何後端 API, DB 仍未刪除. 須點儲存才會送至後端落地.
        本函式亦未提供 undo: 若反悔須直接「不點儲存」, 重整頁面 / 重拉 getUsersList 取回原列.
```

### 三、儲存（saveUsers）

```
001  管理員點紅底「儲存」按鈕（僅 isEditable && isModified 顯示）
002  $ui.updateLoading(true)
003  檢查 isError
004      非空字串:
005          hideLoading + await showCheckYes(isError) 後 return（不送後端）
            (純粹刪除流程下剩餘列已通過先前驗證, 此分支正常情況不會觸發;
             但若刪除前 admin 同時對其他列做過編輯導致驗證錯誤, 此處會先擋下)
006  rows = vo.opt.rows
007  檢查 rows 是否為空 (極端情境: 勾全選刪除) → 為空 hideLoading + await showCheckYes(對應訊息) return
008  自我保護（前端第一道）:
009      尋找 rows 內 row.id === userSelf.id → mySelfRow
010      若 mySelfRow 不存在（自己已被勾選刪除）→ hideLoading + await showCheckYes(cannotDeleteSelf) return
011      若 mySelfRow 存在且 isAdmin !== 'y' → hideLoading + await showCheckYes(cannotDemoteSelf) return
012      若 mySelfRow 存在且 isActive !== 'y' → hideLoading + await showCheckYes(cannotDisableSelf) return
013  剝除 transient flag _isNew (本流程未產生新增列, 但 saveUsers 為共用路徑仍會跑此 map)
014  vo.$fapi.updateUsersList(token, lang, rows) 批次提交（rows 為刪除後的剩餘列）
015      handler 帶入 funCheckAdmin 後呼叫 p.checkTokenAndUpdateUsersList(token, lang, rows, opt)
016          checkToken({ fun: funCheckAdmin })
017              token 為空 / 過期 / 無效 → reject
018              token 有效但 funCheckAdmin 回 false（非 admin）→ b2=false → reject
019                  （注意: 此路徑不分歧錯誤訊息, 與真過期共用同一字串）
020          getUserByToken 取操作者 → operatorId
021          自我保護（後端第二道, 與前端同條訊息）:
022              rows 內找操作者 row → selfRow
023              若 selfRow 不存在（自己已被勾選刪除）→ reject(cannotDeleteSelf)
024              若 selfRow 存在且 isAdmin !== 'y' → reject(cannotDemoteSelf)
025              若 selfRow 存在且 isActive !== 'y' → reject(cannotDisableSelf)
026          updateUsersList(rows, { lang, operatorId }) 委派
027              updateTabItems('users', rows, 'id', { resetOrder: true, lang, operatorId })
028                  ltdtmapping(rows, ds.users.keys) 補齊缺失欄位
029                  resetOrder: rows 依陣列順序重指派 order = k+1（剩餘列重新排序）
030                  ckKey('id'): 表內 id 不可為空或重複 → reject
031                  ckKey('email'): 表內 email 不可為空或重複 → reject
                        （刪除後剩餘列承襲既有合法值, 純粹刪除情境此檢查不會觸發）
032                  ltdtOld = woItems.users.select() 取 DB 既有資料
033                  既有 row password 保留: 將 ltdtOld 內對應 id 的 password (hash) 寫回 rows 該列
                        （此邏輯只處理 rows 內保留下來的列;
                          被刪除目標已不在 rows, 不受此步影響）
034                  ltdtDiffByKey(ltdtOld, rows, 'id') 拆 add / diff / del 三組
                        del 群組 = ltdtOld 中存在但 rows 中缺失的列, 即被勾刪的目標
                        add / diff 群組於純粹刪除情境下為空陣列
035                  del 群組:
036                      procOrm(operatorId, 'users', 'del', r.del) 自 users 表移除被刪列
                            operatorId 用於 audit (userIdUpdate 的記錄路徑由 procOrm 內部處理);
                            del 不級聯清除被刪 user 名下既有 tokens / ips, 須仰賴自然到期或另行清理
037                  add / diff 群組: 純粹刪除情境下 size=0, 不執行 procOrm
038                  return ltdtNew (剝除 password 欄位避免 hash 經 API 洩漏)
039  .catch err → errTemp = err
040  errTemp 非 null:
041      hideLoading + await $dg.showCheckYes(`<userSaveUsersFail>: ${errTemp}`) 後 return
            （改用 modal 強制 admin 點擊確認, 避免 transient toast 漏看後端錯誤訊息）
042  $fapi.getUsersList(token) 重拉同步, 覆寫 vo.users
043      （讓刪除後 order 重排與剩餘列即時顯示）
044  isModified = false（紅底儲存按鈕收起）
045  hideLoading + await showCheckYes(<userSaveUsersSuccess>)
```

## i18n 訊息粒度規則

| 觸發情境 | 對應 key 區位（grep 提示）| 顯示位置 | 粒度規則（spec）|
|---|---|---|---|
| 刪除自己（rows 不含操作者）| `server/procLang.mjs` 找 `cannotDeleteSelf` | CheckYes modal（前端先擋）+ 後端 reject（同訊息）| 前後端統一 |
| 解除自己 admin 權限（與本流程混合操作時）| `server/procLang.mjs` 找 `cannotDemoteSelf` | CheckYes modal + 後端 reject（同訊息）| 前後端統一 |
| 停用自己帳號（與本流程混合操作時）| `server/procLang.mjs` 找 `cannotDisableSelf` | CheckYes modal + 後端 reject（同訊息）| 前後端統一 |
| rows 整張表為空（勾全選刪除）| `server/procLang.mjs` 找 `userAddEmpty` | CheckYes modal | 單一訊息 |
| itemsCheck 為 0 防呆 | `server/procLang.mjs` 找通用「未預期錯誤」key | toast / modal | 防呆路徑，正常 UI 流程不觸發 |
| 後端 token 過期 / 非 admin | `server/procLang.mjs` 找 token 過期相關 key（與 funCheckAdmin 判否共用同一訊息）| CheckYes modal，前綴 `userSaveUsersFail` | 不分歧：身分檢查失敗與真過期共用，不洩露差別 |
| 儲存成功 | `server/procLang.mjs` 找 `userSaveUsersSuccess` | CheckYes modal | — |
| 儲存失敗（包裝層）| `server/procLang.mjs` 找 `userSaveUsersFail` | CheckYes modal | 作為後端 reject 訊息的前綴 |

實際 key 名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴。

## 參數來源

本流程涉及以下執行期參數，**測試讀取順序：settings.json 覆寫值 > WWebSso.mjs opt 預設**：

| 概念 | 來源（優先序）| 測試影響 |
|---|---|---|
| 使用者欄位 schema | `src/schema/users.mjs` | test setup 建 user 的初始狀態 |
| token 有效期 | `settings.json` 對應 key | 測試 token 構造時的 `timeEnd` 計算 |
| initialUsers（伺服器啟動時 seed users）| `settings.json` 對應 key | 若 admin 不慎刪除自己，須由其他 admin 介入或從此 key 重啟伺服器補回 |

實際數字 / 預設值 → 寫測試時讀 `settings.json` 對應 key 或 `src/schema/users.mjs` 的 funNew。

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**：前端 `isError` 攔截 → 前端 rows 空檢查 → 前端自我保護（含 cannotDeleteSelf）→ 後端 `checkToken`（含 funCheckAdmin）→ 後端自我保護（含 cannotDeleteSelf）→ `ckKey('id')` / `ckKey('email')` → procOrm del 寫入。任一層 reject 即整批不落地。
- **粒度**：刪自己 / 解除自己 admin / 停用自己分別用不同訊息；token 失效與身分不足共用同一訊息（不洩露身分檢查）。
- **邊界**：
  - 無獨立 deleteUser API：刪除走 `updateUsersList` 批次儲存共用路徑，由 ltdtDiffByKey 自動推得 del 群組。
  - 無前端二次確認 dialog：點垃圾桶僅執行 rows 過濾 + isModified=true；真正落地需 admin 再點「儲存」。此 gap 即「逃生口」（反悔可不點儲存）。
  - 無 undo 機制：deleteItemsCheck 直接從 vo.users / opt.rows 過濾，不保留 snapshot；反悔僅能重整 / 重拉 getUsersList。
  - 自我刪除保護：rows 內若**不**包含操作者本人（admin 把自己勾選刪除後 rows 移除自己 row），前端 saveUsers 與後端 checkTokenAndUpdateUsersList 皆以 `cannotDeleteSelf` 擋下；前後端兩道防線，訊息一致。
  - 級聯清理：procOrm 'users' 'del' 僅刪 users 表，不級聯清除被刪 user 名下既有 tokens / ips；須仰賴自然到期或另行清理。
- **契約**：
  - `updateUsersList` 走批次 upsert：整表 `ltdtDiffByKey` 一次同步 add / diff / del；若 admin 同時對其他列做過編輯，任一驗證錯誤即整批不落地（含本次刪除）。
  - 儲存成功後立即重拉 `getUsersList` 同步剩餘列與 resetOrder 後的 order。
  - API 回傳前剝除 password 欄位，避免 hash 從 API 流出。
