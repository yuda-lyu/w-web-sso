# 後台重設使用者密碼流程

> **設計策略**：管理員直接產生符合策略之隨機密碼塞給使用者，**不走 reset 連結機制**、**不限時**。改以 `users.isForceChangePw='y'` 旗標強制使用者下次登入後立即變更為自訂密碼。

## 觸發

管理員於 LayoutContentUsers.vue 後台 Users list 對某使用者點擊「Reset password」按鈕。

## 重要流程

> 編號規則:
> - `**E2E-NNN**`: UI baseline 測試, 對應 `test/e2e-resetpassword.test.mjs` + `test/pics/resetpassword/resetpassword-{lang}-E2E-NNN-*.png`
> - `**API-NNN**`: 後端契約測試 (無 baseline), 對應 `test/api-resetpassword.test.mjs`
> - `**UNIT-NNN**`: unit 測試, 對應 `test/unit-genRandomPassword.test.mjs`

### 一、管理員觸發

- **E2E-001** 管理員於後台點 Reset password, CheckYesNo modal 開啟 (E2E-001-admin-ui-modal-opened)
- **E2E-002** 接 E2E-001 點 No 後, modal 關 + DB 不變 + 無 unhandled rejection (E2E-002-admin-ui-cancel-clean)
- **E2E-003** 點 Yes 後, success alert + DB password 變 + isForceChangePw='y' (E2E-003-admin-ui-success-alert)
- **E2E-004** admin 對自己列點 Reset password 後再點 Yes, 出現 self-reject alert 且 admin DB 不變 (E2E-004-admin-ui-self-reject-alert)
- **API-001** API 直呼觸發成功, DB password 變更 + isForceChangePw='y' + 回應無明文 (API-001-happy-path-side-effect)
- **API-002** 管理員觸發成功但寄信失敗（如 SMTP 不通）, 仍視為觸發成功（密碼已重設、isForceChangePw 已寫入）, 須由管理員透過其他管道告知使用者新密碼或重新觸發 (API-002-smtp-fail-still-success)
- **API-003** API 直呼 admin 對自己, reject 'cannot reset self' (API-003-cannot-reset-self)
- **API-004** 一般使用者透過 API 直接呼叫觸發 reset, 後端拒絕（須 admin 權限）(API-004-forbidden-non-admin)
- **API-005** API 直呼帶不存在 userId, reject 'user not found' (API-005-user-not-found)
- **API-006** API 直呼帶空字串 userId, reject 'invalid userId' (API-006-invalid-userId-empty)
- **UNIT-001** 隨機密碼產出符合 passwordPolicy (UNIT-001a~d)

### 二、使用者收信並登入

- **E2E-005** 使用者持新密碼登入, 帳密通過驗證後, 前端偵測 `userSelf.isForceChangePw === 'y'`, 顯示 CheckYes 提示密碼已被管理員重設 (E2E-005-checkyes-prompt)
- **E2E-006** 使用者點 CheckYes 的 OK 後, 進入 user view 並**自動展開變更密碼表單**（使用既有變更密碼 UI）, 強制變更模式下「取消」按鈕**直接隱藏**只剩「送出」一條路（避免使用者繞過強制變更繼續使用; 不改 cancel 行為以維持既有按鈕邏輯單純）(E2E-006-force-form-expanded, 內含 `cancelCount === 0` 斷言驗證 cancel 隱藏)
- **API-007** 使用者收信, 信中含帳號 + 明文新密碼, 不含連結 (驗 template 含 {account}/{newPassword} 且不含 http://) (API-007-email-content-template)
- **API-008** 使用者已登入但其他裝置仍持有舊 token, 該 token 因仍有效暫不受影響, 但下次該裝置 session 結束後須以新密碼登入（**已知 trade-off**, 不主動清除 user 所有 tokens 以保簡單）(API-008-multi-device-tokens-preserved)

### 三、使用者完成強制變更

- **E2E-007** 強制變更密碼成功, 表單收回且 isForceChangePw='n' (E2E-007-after-success)
- **E2E-008** force mode 空舊密, 跳 inline 紅字「請輸入舊密碼」(E2E-008-inline-error-old-password-empty)
- **E2E-009** force mode 新密碼≠確認密碼, 跳 inline 紅字「不一致」(E2E-009-inline-error-new-not-match-confirm)
- **E2E-010** force mode 新密碼不符策略, 跳 inline 紅字「長度不足」等 (E2E-010-inline-error-new-not-meet-policy)
- **E2E-011** force mode 舊密碼錯, 跳 inline 紅字「變更失敗」(E2E-011-inline-error-old-password-wrong)
- **E2E-012** 強制變更頁點 logout 後再以 raw 密碼重登, 仍見 CheckYes (E2E-012-logout-relogin-still-force)
- **E2E-013** force=y 訪問 ?view=backstage, 仍被拉回 user view 強制變更 (E2E-013-force-redirect-to-user)
- **API-009** 變更成功後寄通知信 (API-009-notification-email-template)

## 執行流程

### 一、管理員觸發重設

```
001  管理員於 LayoutContentUsers.vue 點擊目標使用者列的「Reset password」按鈕
002  前端 modifyItemPasswordById(id):
003      $dg.showCheckYesNo「確定對 {account} 重設密碼？」二次確認
004      確認後 $ui.updateLoading(true)，呼叫 $fapi.adminResetUserPassword(token, lang, userId)
005      .then alert「已重設並寄送新密碼至 {email}」
006      .catch 依錯誤類型 alert (forbidden / user not found / cannot reset self / 其他)
007      .finally $ui.updateLoading(false)
008  後端 WWebSso.mjs adminResetUserPassword handler → p.adminResetUserPassword
009      checkToken 驗證操作者 token 有效（無效 / 過期 / 重複 → reject）
010      getUserByToken 取出操作者 → 檢查 isAdmin === 'y'
011          非 admin: reject('forbidden')
012      檢查 userId 為空字串
013          空: reject('invalid userId')
014      _getGenUserByKV('id', targetUserId) 取目標使用者
015          查無: reject('user not found')
016      檢查不可對自己觸發
017          operatorId === targetUserId: reject('cannot reset self')
018      呼叫 genRandomPassword(passwordPolicy, account) 產生符合策略的隨機新密碼
019      雜湊新密碼: hashPassword(newPassword, salt)
020      save 至 users 表:
              password = hashedPassword
              isForceChangePw = 'y'
              timePasswordChanged = now
021      try: 寄送重設密碼信，內含明文新密碼（不含連結）
              讀 server/template/resetPasswordEmail-{lang}.html，
              模板代入 sender / name / account / newPassword
022      catch: 僅 srLog.error, 不 reject（密碼已寫入，寄信失敗可由管理員另外通知）
023      回傳 { state: 'success' }（**不回傳明文密碼給前端**，避免操作者得知；明文僅在寄信當下使用後即釋放）
```

### 二、使用者收信並登入

```
001  使用者收到「您的密碼已被管理員重設」信件，內含 account + 新密碼明文
002  使用者前往登入頁，輸入帳號 + 新密碼
003  進入一般登入流程（procCore loginByAccountAndPassword 一路驗證）
004  登入成功, 前端取得 userSelf 物件（含 isForceChangePw 欄位）
005  PageLogin login .then 內檢查 userSelf.isForceChangePw === 'y'
006      'y':
007          不執行 useRedir 轉址（即使原本 view='login' 該轉跳）
008          顯示 $dg.showCheckYes 提示密碼已被管理員重設
009          使用者按 OK
010          updateViewState('user') 進入使用者資訊頁（無視原 URL view 參數）
011      'n' 或空:
012          照原本流程（依 view 轉址或進指定頁）
```

### 三、PageUser 強制展開變更密碼表單

```
001  PageUser.vue mounted 時檢查 userSelf.isForceChangePw === 'y'
002      'y':
003          自動 clickChangePassword（展開變更密碼表單）
004          UI 模式進入「強制變更模式」（forceChangePwMode = true）
005          隱藏 logout 以外的其他導覽（避免使用者跳出去）
006          「取消」按鈕直接隱藏（只剩送出，使用者要離開只能 logout）
007  使用者填寫舊密碼（管理員給的隨機新密碼）+ 新密碼 + 確認密碼，點送出
008      呼叫既有 submitChangePassword 流程
009      後端 checkTokenAndChangePassword 在成功 save 時多寫一欄: isForceChangePw='n'
010      變更成功 → 收起表單 + alert「密碼變更成功」
011      forceChangePwMode 解除（因 userSelf.isForceChangePw 已是 'n'）, 一般 user view 行為恢復
```

### 四、隨機密碼產生器（後端 helper）

```
位置：server/genRandomPassword.mjs（獨立 helper, 由 procCore 引入）
簽名：genRandomPassword(passwordPolicy, account) → 字串

邏輯：
001  讀 passwordPolicy（minLength / maxLength / requireLetter / requireUppercase /
        requireLowercase / requireDigit / requireSpecial / forbiddenChars 等）
002  目標長度: 取 minLength、maxLength 與 helper 內預設下限三者夾出的合理區間（實際值見 genRandomPassword.mjs 頂部常數）
003  字元池:
        letters = a-z, A-Z（依 requireUppercase / requireLowercase 細分）
        digits = 0-9
        specials = 標點符號集合, 並依 forbiddenChars 過濾掉禁用字元（預設排除 \）
004  生成迴圈（最多 N 次嘗試，N 為 helper 內常數）:
005      初始化 password = []
006      若 requireLetter: 隨機抽 1 字 letters
007      若 requireUppercase: 隨機抽 1 大寫
008      若 requireLowercase: 隨機抽 1 小寫
009      若 requireDigit: 隨機抽 1 字 digits
010      若 requireSpecial: 隨機抽 1 字 specials
011      補滿到目標長度，每位置從合法字元池隨機抽
012      shuffle 打亂順序
013      呼叫 isUserPw(password, passwordPolicy, { account })  // 復用既有檢查
014          通過: return password
015          不通過（最常見：與 account 連續字元衝突 / 命中黑名單）:
016              繼續下一輪嘗試
017  嘗試上限後仍失敗: throw 'cannot generate random password matching policy'
        （極少發生，除非 passwordPolicy 設定不合理）
```

## i18n 訊息粒度規則

| 觸發情境 | 對應 key 區位（grep 提示）| 顯示位置 | 粒度規則（spec）|
|---|---|---|---|
| 管理員點 Reset password 二次確認 modal | `server/procLang.mjs` 找 `adminResetPasswordConfirm` 相關 | CheckYesNo modal | 顯示目標 account 的確認句 |
| 觸發成功 alert | `server/procLang.mjs` 找 admin reset 成功訊息 key | 全頁 alert | 顯示已寄送至目標 email |
| API 拒絕 `cannot reset self` / `forbidden` / `user not found` / `invalid userId` | reject 訊息為英文字串，由前端 catch 後再對應語系 | 全頁 alert | 各自具體訊息（後台對 admin 顯示具體錯誤，不需混淆統一訊息） |
| 使用者登入後 CheckYes 強制變更提示 | `server/procLang.mjs` 找 `userForceChangePwPrompt` | CheckYes modal | 通知密碼已被管理員重設、按 OK 後變更 |
| 強制變更模式下變更密碼 inline 錯誤 | 沿用「使用者變更密碼」流程的 i18n 規則 | 各欄位下方紅字 | 同變更密碼流程 |
| 重設密碼通知信標題 | `server/procLang.mjs` 找 `resetPwEmTitle` | Email subject | 標題提示密碼已被重設 |

實際 key 名與翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應前綴。

## 參數來源

本流程涉及以下執行期參數，**測試讀取順序：`settings.json` 覆寫值 > `server/WWebSso.mjs` opt 預設**：

| 概念 | 來源（優先序）| 測試影響 |
|---|---|---|
| 密碼策略（長度上下限 / 字元類要求 / 禁用字元 / 共用黑名單 / 與帳號連續字元門檻）| `settings.json` `passwordPolicy` → opt 預設 | `genRandomPassword` 依此產出符合策略密碼；構造強制變更失敗 case 須對應 |
| 隨機密碼目標長度公式 | hardcode `server/genRandomPassword.mjs` 內 | 測試驗 length 須讀該檔頂部變數 |
| 隨機密碼 special 字元池與排除字元 | hardcode `server/genRandomPassword.mjs` 內，並再依 `passwordPolicy.forbiddenChars` 過濾 | 測試驗 specials 須讀該檔頂部變數 |
| 隨機密碼生成嘗試上限 | hardcode `server/genRandomPassword.mjs` 內 | 測試「policy 設定不合理拋錯」case 用 |
| 鹽 salt | `settings.json` `salt` → opt 預設 | 比對 reset 後 password hash 須用同 salt |
| Email 寄信設定（SMTP）| `settings.json` `emSrc*` 系列 | SMTP 不通會等網路 timeout（測試須給寬鬆 timeout，~30s），且寄信失敗不阻擋 reset 結果 |

實際數字 / 字元集 → 寫測試時讀 `settings.json` 對應 key，若無 → 讀 `server/WWebSso.mjs` opt 預設值或 `server/genRandomPassword.mjs` 頂部常數。

## Email 模板規格

| 規則（spec）|
|---|
| 信件**不含**任何連結（避免 phishing 與「reset 連結」攻擊面） |
| 信件**僅含**明文新密碼 + 帳號（明文僅信件當下使用，**不存 DB 也不回傳前端**） |
| 使用者收信後首次登入**強制變更密碼**（後端寫入 `isForceChangePw='y'`，前端登入後檢查並導向變更流程）|
| 模板分中英文：`server/template/resetPasswordEmail-{eng,cht}.html` |
| Placeholder：`{name}` / `{sender}` / `{account}` / `{newPassword}`，由 `procCore.renderEmailBody('resetPasswordEmail', lang, kp)` 代入 |
| 信件不寄任何 token（無 reset 連結即無 token）|

實際模板內容（標題 i18n key、body HTML）→ 讀 `server/procLang.mjs` 的 `resetPwEmTitle` 與 `server/template/resetPasswordEmail-{eng,cht}.html` 對應檔。

## 安全性考量

| 項目 | 規則（spec）|
|---|---|
| 信件含明文新密碼 | 採此設計取代 reset 連結；緩解措施為強制使用者首次登入後變更密碼 |
| 隨機密碼強度 | 由 `genRandomPassword` 產生符合 `passwordPolicy` 的密碼 |
| 不限時 | reset 流程無 token / 無連結，故無限時概念；`isForceChangePw='y'` 為常駐旗標直到使用者完成變更 |
| Admin 對自己重設 | 後端拒絕（`cannot reset self`），避免自我鎖死 |
| 一般使用者呼叫 API | 後端拒絕（`forbidden`），須 admin 權限 |
| 多裝置 token 不清除 | admin reset **不主動清** 該 user 所有 tokens（**已知 trade-off**：若疑似被盜需 admin 額外手動清除）|
| 密碼不記錄 log | srLog 僅記錄 event / userId，**不記錄 newPassword 明文** |
| 操作者不知道密碼 | 後端不回傳明文密碼給前端 API 回應 |
| 強制變更頁面不可繞過 | UX 設計「取消」按鈕**直接隱藏**，使用者要離開只能 logout；再次登入仍被拉回強制變更頁直到完成 |

## spec 規則摘要（粒度 / 邊界 / 順序 / 契約）

- **驗證順序**（admin 觸發）：`checkToken` → `isAdmin='y'` → `userId` 非空 → user 存在 → 操作者 ≠ 目標（不可對自己觸發）→ 產生符合策略隨機密碼 → hash → save（含 `isForceChangePw='y'`）→ 寄信。
- **驗證順序**（使用者收信並登入後）：正常登入路徑 → 前端檢查 `userSelf.isForceChangePw='y'` → 不執行 redir → CheckYes 提示 → 進入 user view → PageUser mounted 自動展開變更密碼表單。
- **粒度**：
  - API 拒絕訊息（`forbidden` / `user not found` / `cannot reset self` / `invalid userId`）**各自具體訊息**（後台對 admin 顯示，不需混淆統一訊息）。
  - 強制變更模式下變更密碼錯誤訊息**沿用變更密碼流程的 i18n 規則**（後端 reject 統一「變更失敗」）。
- **邊界**：
  - 信件**不含任何連結**、**僅含明文新密碼 + 帳號**（避免 phishing 與 reset 連結攻擊面）。
  - 寄信失敗**不阻擋 reset 結果**（密碼已 save，由 admin 另外通知使用者）。
  - **不限時**：reset 流程無 token / 無連結，`isForceChangePw='y'` 為常駐旗標直到使用者完成變更。
  - **多裝置既有 token 不清除**（trade-off：simplicity；若疑似被盜需 admin 另外手動清）。
  - 強制變更頁「取消」按鈕**直接隱藏**，使用者要離開只能 logout；再次登入仍被拉回強制變更頁。
- **契約**：
  - 後端**不回傳明文新密碼**給前端 API（操作者不知道密碼）。
  - `srLog` 僅記錄 event / userId，**不記錄 newPassword 明文**。
  - 強制變更完成後後端清 `isForceChangePw='n'`（與變更密碼流程共用 save 路徑）。
  - 隨機密碼產生器（`server/genRandomPassword.mjs`）依 `passwordPolicy` 產出符合策略密碼；嘗試上限內仍失敗則 throw。
  - Email 模板路徑：`server/template/resetPasswordEmail-{eng,cht}.html`；placeholder 由 `procCore.renderEmailBody('resetPasswordEmail', lang, kp)` 代入。
