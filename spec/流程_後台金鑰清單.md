# 後台金鑰清單流程

## 觸發

管理員登入後台後，於左側導覽點「Tokens list」/「金鑰清單」進入金鑰（登入 token）清單頁（`LayoutContentTokens.vue`）。此頁列出系統現存的登入 token（SSO session）與應用系統金鑰（`isApp='y'`），提供管理員檢視、調整時間欄、設定應用系統金鑰之權限、刪除（撤銷 session）與儲存。

版面：標題列下方為功能列（「編輯模式」開關、「顯示欄位」按鈕；編輯模式下勾選列後出現刪除鈕、有修改時出現儲存鈕），其下為表格；表格欄位依序為「金鑰」「使用者主鍵」「是否為應用系統金鑰」「應用系統權限」「金鑰創建時間」「金鑰到期時間」「金鑰更新時間」（eng：Token / ID of the user / For app / App permissions / Created time / End time / Updated time）。進入時是否為編輯模式依 settings `modeEditTokens`（本部署為開）。

權限：後端 `getTokensList` / `updateTokensList` 以 `{ fun: funCheckAdmin, perm: 'readTokens' / 'writeTokens' }` 包裝（`server/WWebSso.mjs` 之 kpfun `getTokensList` / `updateTokensList`）——使用者 token 須為管理者；應用系統金鑰須具對應權限（ADR-069）；token 無效／過期／權限不足一律 reject `tokenExpired`。主選單之「金鑰清單」僅管理者可見。

## 重要流程

- **E2E-001**
  - title: 進入金鑰清單檢視全部金鑰
  - description: 管理員從主選單點選「金鑰清單」後，右側內容區以表格列出系統現存的全部金鑰，欄位依序為「金鑰」「使用者主鍵」「是否為應用系統金鑰」「應用系統權限」「金鑰創建時間」「金鑰到期時間」「金鑰更新時間」，較右側的欄位需橫向捲動表格才看得到。已勾選「是否為應用系統金鑰」的列，其「使用者主鍵」留白，改於「應用系統權限」欄以標籤列出該金鑰具備的權限，欄寬不足時其餘項目收合為「+」接數字的標籤；一般使用者的金鑰則不顯示權限。此頁只供檢視時不會寫入任何資料；功能列的「編輯模式」開關開啟時，可進一步調整欄位、刪除金鑰或設定權限後儲存。若表格沒有任何列，請重新登入後再進入。適合定期檢視有哪些使用者與應用系統持有有效金鑰。
  - flow:
    - 測試資料：admin user（`isAdmin='y'` / `isActive='y'` / `timeVerified` 有值）+ 其有效 admin session token（固定字串）；另 seed 6 筆登入 token（各具未來固定 `timeEnd`，固定值以免 pixel 浮動）：test-token-1～3 為 `isApp='n'`；test-token-4 為 `isApp='y'`、perms 空（僅基本權限）；test-token-5 為 `isApp='y'`、perms 讀金鑰＋讀統計；test-token-6 為 `isApp='y'`、perms 全部 6 項（有效權限 7 項，欄寬不足以收合顯示）。
    - 操作：以已登入 admin（localStorage 已具有效 admin token）進入後台 → 點側欄「Tokens list」/「金鑰清單」→ 確認進入編輯模式（Edit mode）。
    - 驗證（等 ag-grid 載入穩定後）：
      1. 語意：表格可見 seed 之 token 列（含其一之 token 字串）。
      2. 視覺：`E2E-001-list-loaded`（框住表格整個，含標頭列、過濾列與全部資料列；應用系統金鑰列之「應用系統權限」欄可見權限標籤，test-token-6 列收合為「+」接數字之標籤）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 admin user / token / 6 筆 test token，保留 base seed。
    - 備註：1280 寬時「金鑰更新時間」欄位於可視範圍外；權限標籤之收合由 `AppPermsTags.vue` 依儲存格實寬計算（cht 全部權限顯示 3 個標籤接「+4」，eng 顯示 2 個接「+5」，見 `spec/evidence/2026-09-25-tokens-perms-ui-probe.log`）。

- **E2E-002**
  - title: 修改金鑰欄位並儲存（以改為應用系統金鑰為例）
  - description: 管理員從主選單點選「金鑰清單」後，在「編輯模式」開啟時可直接修改表格中的欄位，例如勾選某列的「是否為應用系統金鑰」，把一般金鑰改為應用系統金鑰；修改後功能列隨即出現紅色圓形、提示文字為「儲存變更」的儲存按鈕，點擊後畫面顯示「儲存金鑰數據成功」，點「確認」關閉，該列即維持修改後的內容，此例中「使用者主鍵」改為留白，「應用系統權限」欄出現僅含「讀使用者」的權限框。修改只在點擊儲存按鈕後才寫入，未儲存即離開頁面則修改不會保留。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，重新登入後再修改並儲存即可。適合調整金鑰的用途與到期時間等設定。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 `isApp='n'` 之 test token，即 test-token-1）。
    - 操作：進入 Tokens list（編輯模式）→ 切換該列 `isApp` checkbox（`n`→`y`，使表格進入「已修改」態、Save 按鈕出現）→ 點 Save。
    - 驗證（多階段，同一 browser 內完成）：
      1. 語意：出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；且 DB 中該 token 之 `isApp` 已由 `n` 變 `y`。
      2. 視覺 stage1（isApp cell 觸發態）：toggle 後、Save 前，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-1-isapp-toggled-before-save.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-1 列的 isApp 欄 cell（已切換為勾選態）。
      3. 視覺 stage2（成功 modal）：Save 後、點 OK 前，System message modal 浮出穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-2-save-success-modal.png` 視覺一致（pixelmatch 容差）；觀察點為 WDialog 內層 modal panel，顯示儲存成功訊息與確認按鈕。
      4. 視覺 stage3（結果列）：點 OK 關閉 modal、等 grid idle 穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-3-toggle-isapp-result-row.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-1 所在列（isApp 欄已切換為 `y`，其「應用系統權限」欄隨之出現僅含基本權限「讀使用者」/「Read users」標籤之權限框，「使用者主鍵」欄改為留白）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 seed，保留 base seed。
    - 備註：以 `isApp` 勾選框之切換為「修改欄位」之代表——與修改 timeEnd 走同一 `updateTokensList` 差異更新路徑、終態同為成功 modal；不用 timeEnd 是因其欄為 WTimeminute 自訂渲染、操作路徑不同且較不穩定。多階段截圖 3 張各有獨立 baseline。

- **E2E-003**
  - title: 勾選金鑰刪除並儲存以撤銷登入
  - description: 管理員從主選單點選「金鑰清單」後，在「編輯模式」開啟時勾選某列金鑰左側的選取框，功能列隨即出現提示文字為「刪除勾選金鑰」的垃圾桶按鈕，點擊後該列自表格移除，再點提示文字為「儲存變更」的紅色圓形儲存按鈕，畫面顯示「儲存金鑰數據成功」。儲存後該金鑰即失效，持有者須重新登入；刪除的若是應用系統金鑰，該應用系統即無法再以它呼叫單一登入系統。刪除只在點擊儲存按鈕後才寫入，儲存前重新整理頁面即可恢復。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，重新登入後再操作即可。適合強制登出特定使用者或停用應用系統。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 test token，即 test-token-2）。
    - 操作：進入 Tokens list（編輯模式）→ 勾選目標列之列選取 checkbox → 點垃圾桶（刪除）→ 點 Save。
    - 驗證（多階段，同一 browser 內完成）：
      1. 語意：出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；且 DB 中該 token 已不存在、其餘 test token 仍在（撤銷該 session）。
      2. 視覺 stage1（已選取列觸發態）：勾選後、點垃圾桶/Save 前，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-1-row-selected-before-save.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-2 所在列（pinned-left + center 聯集，呈已選取高亮態）。
      3. 視覺 stage2（成功 modal）：勾選 → 刪 → Save 後成功 modal 浮出穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-2-delete-row-save-success.png` 視覺一致（pixelmatch 容差）；觀察點為 WDialog 內層 modal panel，顯示儲存成功訊息。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 seed，保留 base seed。
    - 備註：後端以差異更新判定該列被移除而刪除（`updateTabItems` 之 del），即撤銷該 session；多階段截圖 2 張各有獨立 baseline。

- **E2E-004**
  - title: 儲存時登入已逾時顯示失敗訊息
  - description: 管理員修改金鑰清單後點擊儲存按鈕時，若其登入已逾時或已失去管理者身分，畫面顯示「儲存金鑰數據失敗」接「登入逾時，請重新登入。」，表格中的修改不會寫入。點「確認」關閉後，修改仍留在畫面上但尚未儲存，須重新登入後再次修改並儲存。適合了解儲存失敗時的處理方式。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 `isApp='n'` 之 test token）；本案模擬「填完表格後 admin token 才到期」——於進頁、改完欄位後、Save 前將 admin token 之 `timeEnd` 設為過去（過期）。

    - 驗證（等失敗 modal 浮出穩定後）：
      1. 語意：出現「Failed to save tokens」/「儲存金鑰數據失敗」之 System message modal；且 DB 中該 token 之 `isApp` 仍為 `n`、test token 數量不變（後端 reject、無寫入）。
      2. 視覺：與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-004-token-expired-save-fail.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 admin token 效期，保留 base seed。
    - 備註：後端 `checkToken` reject 後對外 key 為 `tokenExpired`，前端以 `$tErr` 翻成語系文字接於「儲存金鑰數據失敗」之後；與 E2E-002 共同覆蓋儲存動作之成敗分支。

- **E2E-005**
  - title: 為應用系統金鑰勾選權限並儲存（以讀金鑰為例）
  - description: 管理員從主選單點選「金鑰清單」後，已勾選「是否為應用系統金鑰」的列會在「應用系統權限」欄顯示權限框，框內以標籤列出該金鑰目前具備的權限。點擊權限框會展開「應用系統權限」清單，其中「讀使用者」為基本權限，恆為勾選且不可取消，其餘 6 項在「編輯模式」開啟時可勾選。以勾選「讀金鑰」為例，勾選後功能列隨即出現紅色圓形、提示文字為「儲存變更」的儲存按鈕，點擊後畫面顯示「儲存金鑰數據成功」，點「確認」關閉，該列權限框即增列「讀金鑰」標籤，該應用系統自此可讀取金鑰清單。勾選只在點擊儲存按鈕後才寫入。清單中「寫使用者」「讀金鑰」「寫金鑰」旁標示「等同管理者權限」，授予後該應用系統可取得管理者層級的操作能力，授予前請確認其必要。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，多為登入逾時，重新登入後再勾選並儲存即可。適合依應用系統的介接需要逐項開放後台功能。
  - flow:
    - 測試資料：同 E2E-001；目標列為 test-token-4（`isApp='y'`、perms 空，僅基本權限）。
    - 操作：進入 Tokens list（編輯模式）→ 點 test-token-4 列之應用系統權限框 → 於展開之清單點「讀金鑰」/「Read tokens」→ 點功能列之儲存鈕（清單仍開啟）→ 於成功訊息點「確認」/「OK」。
    - 驗證：
      1. 語意：操作前 test-token-4 呼叫後台金鑰清單（kpfun `getTokensList`）被拒；勾選後清單未關閉即出現儲存鈕；出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；DB 中 test-token-4 之 perms 為 `['readTokens']`；儲存後 test-token-4 呼叫 `getTokensList` 立即成功（端到端不變式）。
      2. 視覺：`E2E-005-1-click-perms`（框住 test-token-4 列之應用系統權限框整顆，內含「讀使用者」標籤）→ `E2E-005-2-perms-list`（框住展開之權限清單浮層整個，含標頭「應用系統權限」）→ `E2E-005-3-check-read-tokens`（框住清單中「讀金鑰」整列，含勾選框、名稱與「等同管理者權限」提示）→ `E2E-005-4-read-tokens-checked`（框住權限清單浮層整個，「讀金鑰」已勾選）→ `E2E-005-5-click-save`（框住功能列之儲存鈕整顆，權限清單仍開啟）→ `E2E-005-6-save-success-modal`（框住成功訊息之對話框面板）→ `E2E-005-7-perms-result`（點「確認」關閉後，框住 test-token-4 列之應用系統權限框，含「讀使用者」「讀金鑰」標籤）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 admin user / admin token / 6 筆 test token（含本案寫入之 perms），保留 base seed；回驗 tokens 表無 `id-test-token-*` 列。

- **E2E-007**
  - title: 非編輯模式下檢視應用系統權限（以全部權限為例）
  - description: 管理員從主選單點選「金鑰清單」後，點擊功能列左側的「編輯模式」開關將其關閉，表格即改為唯讀，列選取框與拖曳把手隨之消失。此時點擊應用系統金鑰列的權限框仍會展開「應用系統權限」清單，可檢視該金鑰具備的全部權限，包含表格中因欄寬不足而收合為「+」接數字的項目；清單各項皆不可勾選，點選不會改變設定，也不會出現儲存按鈕。適合只需查閱應用系統權限、避免誤改時使用；需要調整時再開啟「編輯模式」。
  - flow:
    - 測試資料：同 E2E-001；目標列為 test-token-6（`isApp='y'`、perms 全部 6 項）。
    - 操作：進入 Tokens list（編輯模式開啟）→ 點功能列之「編輯模式」/「Edit mode」開關使其關閉 → 點 test-token-6 列之應用系統權限框 → 於清單點「讀統計」/「Read statistics」（試圖取消）。
    - 驗證：
      1. 語意：關閉後表格無列選取框；清單 7 項皆勾選且皆不可勾選；點「讀統計」後仍 7 項勾選、不出現儲存鈕；清單可見「基本權限，恆具備」/「Basic permission, always granted」；DB 中 test-token-6 之 perms 不變。
      2. 視覺：`E2E-007-1-click-edit-mode`（框住功能列之「編輯模式」開關整顆含文字）→ `E2E-007-2-view-mode`（框住表格整個，列選取框與拖曳把手已消失）→ `E2E-007-3-click-perms`（框住 test-token-6 列之應用系統權限框整顆，含收合之「+」接數字標籤）→ `E2E-007-4-perms-list-readonly`（框住展開之權限清單浮層整個，7 項皆勾選且呈不可勾選之灰色）。
    - 雙語：eng / cht 各一輪。
    - 清理：同 E2E-005（本案不寫入）。
    - 備註：非編輯模式之清單由 WInputCheckbox `editable=false` 呈現；「編輯模式」開關之可點層為 WSwitch 之 inline-block 容器（開關與文字）；切換編輯模式會重建表格，開啟中清單之草稿隨之捨棄（`genOpt`）。

## spec 規則摘要

- **權限**：`getTokensList` / `updateTokensList` 之使用者 token 須為管理者（`funCheckAdmin`）；應用系統金鑰依其 perms 須具 `readTokens` / `writeTokens`（ADR-069）；皆不足時對外同為 `tokenExpired`。
- **應用系統權限**（ADR-069）：權限字串 7 個（`readUsers` / `writeUsers` / `readTokens` / `writeTokens` / `readIps` / `writeIps` / `readStats`），多元素為聯集，讀寫互不蘊含；`readUsers` 為基本權限恆具備、不可取消；perms 未設定＝只有基本權限；`writeUsers` / `readTokens` / `writeTokens` 可取得管理者權限，清單以「等同管理者權限」標註。
- **權限清單之寫入時機**：勾選即標記已修改（儲存鈕出現），但只寫入前端表格之草稿；關閉清單或按儲存時寫回該列，按儲存才寫入 DB；非編輯模式清單唯讀；表格重建時草稿捨棄。
- **標準圖通則**：存放 `test/pics/tokens/`，檔名 `tokens-{eng,cht}-E2E-NNN[-<序>-<名>].png`；E2E-005 起每步兩張（點擊前框住要點之元素、點擊後框住有反應之元素），一圖一框；權限清單浮層框其面板整個（含標頭），不框清單外之空白。
- **粒度**：操作結果（成功 / 失敗）一律 `showCheckYes` 持久 modal（須確認讀過、可做 e2e pixel + 語意斷言）；非預期例外才用 `$alert` toast。
- **邊界**：`isError` 恆為 `''`，前端驗證攔截分支為死碼；無「手動新增」列。刪除某列即撤銷該 session。
- **契約**：Save 前開 loading、`finally` 一處關 loading；每個 `await showCheckYes(...)` 前先關 loading（modal 阻斷，避免 loading 疊著）。

## 已知落差

- **本 spec 原載「僅具 admin 權限的有效 token 可存取」不成立（設計事實；發現於 2026-09-25）**：2026-09-25 前，應用系統金鑰（`isApp='y'`）依 ADR-005 於 `server/procCore.mjs` 之 `_checkTokenByObj` 跳過 `funCheckAdmin`，perms 為空者亦可讀寫金鑰清單（`test/api-apptoken-perms.test.mjs` 改動前紅燈紀錄，見 ADR-069 Context）。使用者可觀察之後果：任一應用系統金鑰之持有者可經資料通道讀取全部 session 金鑰。層級與歸屬：本專案產品程式碼。處置：依業主 2026-09-25 裁示改為依權限授權（ADR-069），〈觸發〉與〈規則摘要〉已改寫；E2E-005～007 新增。
- **載入金鑰清單失敗時無任何提示（缺陷（待修）；發現於 2026-09-25）**：`LayoutContentTokens.vue` 之 `mounted` 於 `getTokensList` 失敗時只設 `vo.errMsg`，該欄位未宣告於 data 亦未於模板顯示，畫面只呈現無資料列之表格。使用者可觀察之後果：登入逾時或權限不足時看到空白表格而無訊息。層級與歸屬：本專案產品程式碼（姊妹頁 `LayoutContentUsers.vue` / `LayoutContentIps.vue` 同型未查）。處置：待修，本次未改（不在應用系統權限範圍）。
