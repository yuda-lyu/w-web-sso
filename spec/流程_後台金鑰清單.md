# 後台金鑰清單流程

## 觸發

管理員登入後台後，於左側導覽點「Tokens list」進入金鑰（登入 token）清單頁（`LayoutContentTokens.vue`）。此頁列出系統現存的登入 token（SSO session），提供管理員檢視、調整時間欄、刪除（撤銷 session）與儲存。

後端 `getTokensList` / `updateTokensList` 皆以 `funCheckAdmin` 包裝（`server/WWebSso.mjs:1238,1222`），**僅具 admin 權限的有效 token 可存取**；token 無效／過期／非 admin 一律 reject。

## 重要流程

- **E2E-001**
  - title: 管理員進入金鑰清單頁顯示 token 列
  - description: 驗證管理員以有效 admin token 進入後台「Tokens」頁籤後，前端呼叫 getTokensList 取回現有 token 列表並渲染於表格，呈現初始檢視態。此案為金鑰清單流程的入口檢視，後續修改 / 刪除 / 失敗案例皆以此檢視態為起點。
  - flow:
    - 測試資料：admin user（`isAdmin='y'` / `isActive='y'` / `timeVerified` 有值）+ 其有效 admin session token；另 seed 5 筆登入 token（前 3 筆 `isApp='n'`、後 2 筆 `isApp='y'`，各具未來固定 `timeEnd`，固定值以免 pixel 浮動）。
    - 操作：以已登入 admin（localStorage 已具有效 admin token）進入後台 → 點側欄「Tokens list」/「金鑰清單」→ 確認進入編輯模式（Edit mode）。
    - 驗證（等 ag-grid 載入穩定後）：
      1. 語意：表格可見 seed 之 token 列（含其一之 token 字串）。
      2. 視覺：與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-001-list-loaded.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 admin user / token / 5 筆 test token，保留 base seed。

- **E2E-002**
  - title: 管理員修改某列欄位後 Save 成功
  - description: 驗證管理員於金鑰清單表格中修改某列之可編輯欄位並點擊 Save 後，後端 updateTokensList 寫入成功，前端顯示 System message modal 呈現 tokenSaveTokensSuccess「儲存成功」訊息，且 DB tokens 表對應列已更新。屬正常成功路徑案例。（測試以該列 `isApp` checkbox 之切換為「修改欄位」之代表——與修改 timeEnd 走同一 updateTokensList 差異更新路徑、終態同為成功 modal；之所以不用 timeEnd 是其欄為 WTimeminute 自訂渲染、UI 操作路徑不同且較不穩定。）本案例採多階段截圖（3 階段）：stage1 觀察 toggle 後 save 前的 isApp cell 觸發態、stage2 觀察成功 modal 畫面、stage3 觀察 modal 關閉後已切換 isApp 的結果列，各自有獨立 baseline。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 `isApp='n'` 之 test token，即 test-token-1）。
    - 操作：進入 Tokens list（編輯模式）→ 切換該列 `isApp` checkbox（`n`→`y`，使表格進入「已修改」態、Save 按鈕出現）→ 點 Save。
    - 驗證（多階段，同一 browser 內完成）：
      1. 語意：出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；且 DB 中該 token 之 `isApp` 已由 `n` 變 `y`。
      2. 視覺 stage1（isApp cell 觸發態）：toggle 後、Save 前，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-1-isapp-toggled-before-save.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-1 列的 isApp 欄 cell（已切換為勾選態）。
      3. 視覺 stage2（成功 modal）：Save 後、點 OK 前，System message modal 浮出穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-2-save-success-modal.png` 視覺一致（pixelmatch 容差）；觀察點為 WDialog 內層 modal panel，顯示儲存成功訊息與確認按鈕。
      4. 視覺 stage3（結果列）：點 OK 關閉 modal、等 grid idle 穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-002-3-toggle-isapp-result-row.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-1 所在列（isApp 欄已切換為 `y`）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 seed，保留 base seed。

- **E2E-003**
  - title: 管理員勾選刪除某列後 Save 成功
  - description: 驗證管理員勾選金鑰清單某列後執行刪除動作並點擊 Save，後端 diff 後判定該列已被移除（撤銷該 session 之登入態），DB tokens 表對應列消失，前端顯示成功 modal。屬刪除路徑成功案例。本案例採多階段截圖（2 階段）：stage1 觀察勾選後、刪除/Save 前的已選取列觸發態、stage2 觀察成功 modal，各自有獨立 baseline。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 test token，即 test-token-2）。
    - 操作：進入 Tokens list（編輯模式）→ 勾選目標列之列選取 checkbox → 點垃圾桶（刪除）→ 點 Save。
    - 驗證（多階段，同一 browser 內完成）：
      1. 語意：出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；且 DB 中該 token 已不存在、其餘 test token 仍在（撤銷該 session）。
      2. 視覺 stage1（已選取列觸發態）：勾選後、點垃圾桶/Save 前，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-1-row-selected-before-save.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-2 所在列（pinned-left + center 聯集，呈已選取高亮態）。
      3. 視覺 stage2（成功 modal）：勾選 → 刪 → Save 後成功 modal 浮出穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-2-delete-row-save-success.png` 視覺一致（pixelmatch 容差）；觀察點為 WDialog 內層 modal panel，顯示儲存成功訊息。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 seed，保留 base seed。

- **E2E-004**
  - title: Save 時 admin token 失效顯示失敗
  - description: 驗證 Save 觸發時若 admin token 已失效（過期或角色非 admin），後端 checkToken reject，前端顯示 System message modal 呈現 tokenSaveTokensFail「儲存失敗: {錯誤}」訊息，且 DB tokens 表內容不變。屬失敗路徑案例，與成功路徑共同覆蓋 Save 動作的成敗分支。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 `isApp='n'` 之 test token）；本案模擬「填完表格後 admin token 才到期」——於進頁、改完欄位後、Save 前將 admin token 之 `timeEnd` 設為過去（過期）。
    - 操作：進入 Tokens list（此時 token 仍有效）→ 切換目標列 `isApp` checkbox（使 Save 按鈕出現）→（admin token 於 Save 前轉為過期）→ 點 Save。
    - 驗證（等失敗 modal 浮出穩定後）：
      1. 語意：出現「Failed to save tokens」/「儲存金鑰數據失敗」之 System message modal；且 DB 中該 token 之 `isApp` 仍為 `n`、test token 數量不變（後端 reject、無寫入）。
      2. 視覺：與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-004-token-expired-save-fail.png` 視覺一致（pixelmatch 容差）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 admin token 效期，保留 base seed。

## 執行流程

```
001  管理員點 Save, 觸發 saveTokens  [LayoutContentTokens.vue]
002      執行非同步流程 core()
003          開啟 loading
004          檢查 isError  [LayoutContentTokens.vue:853]
005              註: isError computed 恆回傳 ''  [LayoutContentTokens.vue:473]
006                  → 此分支為死碼, 永遠不進入 (showCheckYes 不會被觸發)
007          取得當前 opt.rows 與 admin token
008          呼叫後端 updateTokensList(token, lang, rows)  [LayoutContentTokens.vue:874]
009              checkToken(token, {fun: funCheckAdmin})  [procCore.mjs:1786]
010                  token 無效 / 過期 / 非 admin:
011                      reject  → errTemp 被設值
012              updateTabItems('tokens', rows, 'id', {resetOrder:false}) 差異更新  [procCore.mjs:1776]
013          檢查 errTemp  [LayoutContentTokens.vue:880]
014              非 null (後端 reject):
015                  關 loading, 後端 reject key 經 $tErr 翻成語系文字, 顯示 System message modal 儲存失敗訊息, return  [LayoutContentTokens.vue:881-885]
016          isModified = false
017          關 loading, 顯示 System message modal 儲存成功訊息  [LayoutContentTokens.vue:893]
018      .catch
019          非預期例外 → console.log + $alert toast (anUnexpectedErrorOccurred)
020      .finally
021          關 loading (一處關閉)
```

## i18n 訊息粒度規則

| 觸發情境 | i18n 鍵 (grep `server/procLang.mjs`) | 顯示元件 | 規則 |
|---|---|---|---|
| 儲存成功 | `tokenSaveTokensSuccess` | `showCheckYes` 持久 modal（System message） | 管理員須點 OK 確認讀過 |
| 儲存失敗（後端 reject） | `tokenSaveTokensFail`（後接後端 reject key，如 `tokenExpired`，由前端 `$tErr` 翻成語系文字後接於前綴） | `showCheckYes` 持久 modal | 同上 |
| 非預期例外（外層 catch） | `anUnexpectedErrorOccurred` | `$alert` toast（4 秒自動消失） | 非預期錯誤刻意低調呈現，不阻斷 |

實際翻譯文字 → 寫測試時 grep `server/procLang.mjs` 對應鍵後直接讀取。

## 參數來源

| 概念 | 來源 | 流程影響 |
|---|---|---|
| 操作者 token | 前端 store（登入後 admin token） | 後端以 `funCheckAdmin` 驗證；失效則 Save reject 走失敗 modal |

## spec 規則摘要

- **權限**：`getTokensList` / `updateTokensList` 皆 admin-only（`funCheckAdmin`）。
- **粒度**：操作結果（成功 / 失敗）一律 `showCheckYes` 持久 modal（須確認讀過、可做 e2e pixel + 語意斷言）；非預期例外才用 `$alert` toast。
- **邊界**：`isError` 恆為 `''`，前端驗證攔截分支為死碼；無「手動新增」列。刪除某列即撤銷該 session。
- **契約**：Save 前開 loading、`finally` 一處關 loading；每個 `await showCheckYes(...)` 前先關 loading（modal 阻斷，避免 loading 疊著）。
