# 後台金鑰清單流程

## 觸發

管理員登入後台後，於左側導覽點「Tokens list」/「金鑰清單」進入金鑰（登入 token）清單頁（`LayoutContentTokens.vue`）。此頁列出系統現存的登入 token（SSO session）與應用系統金鑰（`isApp='y'`），提供管理員檢視、新增應用系統金鑰（ADR-095）、調整時間欄、設定系統服務用途金鑰之權限、刪除（撤銷）與儲存。

版面：標題列下方為功能列（「編輯模式」開關、「顯示欄位」按鈕；編輯模式下另有「新增應用系統金鑰」鈕、勾選列後出現刪除鈕、有修改時出現儲存鈕），其下為表格；表格欄位依序為「金鑰」「使用者主鍵」「是否為應用系統金鑰」「用途」「名稱」「應用系統權限」「金鑰創建時間」「金鑰到期時間」「金鑰更新時間」（eng：Token / ID of the user / For app / Usage / Name / App permissions / Created time / End time / Updated time）。進入時是否為編輯模式依 settings `modeEditTokens`（本部署為開）。
- 修改留痕（2026-10-24，ADR-095）：原載欄位無「用途」「名稱」，「是否為應用系統金鑰」可勾選以升級登入 token——升級路徑已關閉（勾選框唯讀，後端清單存檔拒收 `tokenSessionUpgradeNotAllowed`），新增改走「新增應用系統金鑰」；應用系統金鑰之「金鑰到期時間」顯示「不設期限」（不給期限）、使用者主鍵與權杖字串不可編輯；使用者用途之「應用系統權限」顯示「同所綁使用者」（權限即所綁使用者之權限）；系統服務用途之「使用者主鍵」不顯示（其 `userId` 只記建立者，不是身分）；升級前既有之應用系統金鑰（無用途欄）顯示為「系統服務用途」、名稱空白。

權限：後端 `getTokensList` / `updateTokensList` / `createAppToken` 以 `{ fun: funCheckAdmin, perm: 'readTokens' / 'writeTokens' / 'writeTokens' }` 包裝（`server/WWebSso.mjs` 之 kpfun）——使用者 token 與使用者用途之金鑰以（所綁）使用者之管理員身分判定（`funCheckAdmin`: 已驗證、未過期、未封鎖、`isAdmin='y'`、啟用；使用者當前狀態即時判定）；系統服務用途之金鑰須具對應權限（ADR-069）；token 無效／過期／權限不足一律 reject `tokenExpired`。主選單之「金鑰清單」僅管理者可見。

## 重要流程

- **E2E-001**
  - title: 進入金鑰清單檢視全部金鑰
  - description: 管理員從主選單點選「金鑰清單」後，右側內容區以表格列出系統現存的全部金鑰，欄位依序為「金鑰」「使用者主鍵」「是否為應用系統金鑰」「用途」「名稱」「應用系統權限」「金鑰創建時間」「金鑰到期時間」「金鑰更新時間」，較右側的欄位需橫向捲動表格才看得到。已勾選「是否為應用系統金鑰」的列，於「用途」欄標示為「使用者用途」或「系統服務用途」、「名稱」欄為金鑰名稱、「金鑰到期時間」欄顯示「不設期限」；使用者用途的列於「使用者主鍵」欄顯示所綁使用者、「應用系統權限」欄顯示「同所綁使用者」，系統服務用途的列則「使用者主鍵」留白，改於「應用系統權限」欄以標籤列出該金鑰具備的權限，欄寬不足時其餘項目收合為「+」接數字的標籤；一般使用者的金鑰則不顯示用途、名稱與權限。此頁只供檢視時不會寫入任何資料；功能列的「編輯模式」開關開啟時，可進一步新增應用系統金鑰、調整欄位、刪除金鑰或設定權限後儲存。若表格沒有任何列，請重新登入後再進入。適合定期檢視有哪些使用者與應用系統持有有效金鑰。
  - flow:
    - 測試資料：admin user（`isAdmin='y'` / `isActive='y'` / `timeVerified` 有值）+ 其有效 admin session token（固定字串）；另 seed 7 筆金鑰（固定值以免 pixel 浮動）：test-token-1～3 為登入 token（`isApp='n'`，各具未來固定 `timeEnd`）；test-token-4 為升級前之既有應用系統金鑰（`isApp='y'`、無用途欄與名稱欄、perms 空、`timeEnd` 空，視同系統服務用途）；test-token-5 為系統服務用途（名稱 svc-sync、perms 讀金鑰＋讀統計）；test-token-6 為系統服務用途（名稱 svc-admin、perms 全部 6 項，有效權限 7 項，欄寬不足以收合顯示）；test-token-7 為使用者用途（名稱 viewer-key，綁 base seed 之 id-for-viewer）。應用系統金鑰之 `timeEnd` 皆為空（不給期限）。
    - 操作：以已登入 admin（localStorage 已具有效 admin token）進入後台 → 點側欄「Tokens list」/「金鑰清單」→ 確認進入編輯模式（Edit mode）。
    - 驗證（等 ag-grid 載入穩定後）：
      1. 語意：表格可見 seed 之 token 列（含其一之 token 字串）。
      2. 視覺：`E2E-001-list-loaded`（框住表格之標頭列、過濾列與全部資料列，不含列下方空白；應用系統金鑰列於「用途」「名稱」欄可見用途與名稱）。
         - 修改留痕（2026-09-28）：原載「框住表格整個」而框落在表格外框（列下方約 150px 空白一併框入）→ 改框標頭與資料列（技能 §7.2 表格列；本檔 E2E-007-2 同）。
         - 修改留痕（2026-10-24，ADR-095）：原載「test-token-6 列收合為「+」接數字之標籤」於 1280 寬不再位於初始可視範圍——表格多「用途」「名稱」兩欄後，「應用系統權限」欄須橫向捲動才看得到（見 E2E-005～007 之捲動）；本圖改為可見用途與名稱欄。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 admin user / token / 7 筆 test token，保留 base seed。
    - 備註：1280 寬時「應用系統權限」「金鑰創建時間」「金鑰到期時間」「金鑰更新時間」欄位於可視範圍外；權限標籤之收合由 `AppPermsTags.vue` 依儲存格實寬計算（cht 全部權限顯示 3 個標籤接「+4」，eng 顯示 2 個接「+5」，見 `spec/evidence/2026-09-25-tokens-perms-ui-probe.log`；test-token-5 之 3 項於 cht 全數顯示，eng 顯示 2 個接「+1」，見 2026-09-27 標準圖）。

- **E2E-002**（已廢止，編號保留不再使用；理由：ADR-095 起「勾選『是否為應用系統金鑰』把登入 token 升級為應用系統金鑰並儲存」之路徑關閉——前端該勾選框唯讀、後端清單存檔拒收 `tokenSessionUpgradeNotAllowed`（`test/api-apptoken-usage.test.mjs` LIST、`test/unit-saveBaseline.test.mjs` SB-T07）；原案之 6 張標準圖 `tokens-{eng,cht}-E2E-002-*.png` 已刪除。原載標題「修改金鑰欄位並儲存（以改為應用系統金鑰為例）」，其「修改欄位並儲存」之成敗分支由 E2E-003（刪除）、E2E-004（失敗）、E2E-005 / E2E-006（權限）覆蓋；新增應用系統金鑰由 E2E-008 / E2E-009 取代。）

- **E2E-003**
  - title: 勾選金鑰刪除並儲存以撤銷登入
  - description: 管理員從主選單點選「金鑰清單」後，在「編輯模式」開啟時勾選某列金鑰左側的選取框，功能列隨即出現提示文字為「刪除勾選金鑰」的垃圾桶按鈕，點擊後該列自表格移除，再點提示文字為「儲存變更」的紅色圓形儲存按鈕，畫面顯示「儲存金鑰數據成功」。儲存後該金鑰即失效，持有者須重新登入；刪除的若是應用系統金鑰，該應用系統即無法再以它呼叫單一登入系統。刪除只在點擊儲存按鈕後才寫入，儲存前重新整理頁面即可恢復。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，重新登入後再操作即可。適合強制登出特定使用者或停用應用系統。
  - flow:
    - 測試資料：同 E2E-001（目標列為其中一筆 test token，即 test-token-2）。
    - 操作：進入 Tokens list（編輯模式）→ 勾選目標列之列選取 checkbox → 點垃圾桶（刪除）→ 點 Save。
    - 驗證（多階段，同一 browser 內完成）：
      1. 語意：出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；且 DB 中該 token 已不存在、其餘 test token 仍在（撤銷該 session）。
      2. 視覺 stage1（已選取列觸發態）：勾選後、點垃圾桶/Save 前，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-1-row-selected-before-save.png` 視覺一致（pixelmatch 容差）；觀察點為 test-token-2 所在列（pinned-left + center 聯集，呈已選取高亮態）。
      3. 視覺 stage2（成功 modal）：勾選 → 刪 → Save 後成功 modal 浮出穩定後，與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-003-2-delete-row-save-success.png` 視覺一致（pixelmatch 容差）；觀察點為 WDialog 內層 modal panel，顯示儲存成功訊息。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 seed，保留 base seed。
    - 備註：後端以差異更新判定該列被移除而刪除（`updateTabItems` 之 del），即撤銷該 session；多階段截圖 2 張各有獨立 baseline。

- **E2E-004**
  - title: 儲存時登入已逾時顯示失敗訊息
  - description: 管理員修改金鑰清單後點擊儲存按鈕時，若其登入已逾時或已失去管理者身分，畫面顯示「儲存金鑰數據失敗」接「登入逾時，請重新登入。」，表格中的修改不會寫入。點「確認」關閉後，修改仍留在畫面上但尚未儲存，須重新登入後再次修改並儲存。適合了解儲存失敗時的處理方式。
  - flow:
    - 測試資料：同 E2E-001（目標列為 test-token-3，登入 token）；本案模擬「填完表格後 admin token 才到期」——於進頁、改完欄位後、Save 前將 admin token 之 `timeEnd` 設為過去（過期）。
    - 操作：進入 Tokens list（此時 token 仍有效）→ 勾選目標列之選取框並點刪除鈕（使 Save 按鈕出現；修改留痕 2026-10-24：原以切換 `isApp` 勾選框造成修改，ADR-095 起該勾選框唯讀，改以刪除列為「修改」）→（admin token 於 Save 前轉為過期）→ 點 Save。
    - 驗證（等失敗 modal 浮出穩定後）：
      1. 語意：出現「Failed to save tokens」/「儲存金鑰數據失敗」之 System message modal；且 DB 中該 token 之 `isApp` 仍為 `n`、test token 數量不變（後端 reject、無寫入）。
      2. 視覺：與 baseline `test/pics/tokens/tokens-{eng,cht}-E2E-004-token-expired-save-fail.png` 視覺一致（pixelmatch 容差）；框住失敗訊息之對話框面板（「儲存金鑰數據失敗」接「登入逾時，請重新登入。」與確認按鈕；背景表格保留未儲存之修改與儲存鈕）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化資料並復原 admin token 效期，保留 base seed。
    - 備註：後端 `checkToken` reject 後對外 key 為 `tokenExpired`，前端以 `$tErr` 翻成語系文字接於「儲存金鑰數據失敗」之後；與 E2E-003（成功）、E2E-005 / E2E-006（權限）共同覆蓋儲存動作之成敗分支（原載「與 E2E-002 共同覆蓋」，E2E-002 已於 2026-10-24 廢止）。

- **E2E-005**
  - title: 為應用系統金鑰勾選權限並儲存（以讀金鑰為例）
  - description: 管理員從主選單點選「金鑰清單」後，已勾選「是否為應用系統金鑰」的列會在「應用系統權限」欄顯示權限框，框內以標籤列出該金鑰目前具備的權限。點擊權限框會展開「應用系統權限」清單，其中「讀使用者」為基本權限，恆為勾選且不可取消，其餘 6 項在「編輯模式」開啟時可勾選。以勾選「讀金鑰」為例，勾選後功能列隨即出現紅色圓形、提示文字為「儲存變更」的儲存按鈕，點擊後畫面顯示「儲存金鑰數據成功」，點「確認」關閉，該列權限框即增列「讀金鑰」標籤，該應用系統自此可讀取金鑰清單。勾選只在點擊儲存按鈕後才寫入。清單中「寫使用者」「讀金鑰」「寫金鑰」旁標示「等同管理者權限」，授予後該應用系統可取得管理者層級的操作能力，授予前請確認其必要。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，多為登入逾時，重新登入後再勾選並儲存即可。適合依應用系統的介接需要逐項開放後台功能。
  - flow:
    - 測試資料：同 E2E-001；目標列為 test-token-4（升級前之既有應用系統金鑰，視同系統服務用途；perms 空，僅基本權限）。
    - 操作：進入 Tokens list（編輯模式）→ 橫向捲動表格使「應用系統權限」欄進入可視範圍（修改留痕 2026-10-24：表格多「用途」「名稱」欄後，該欄於 1280 寬初始不在可視範圍）→ 點 test-token-4 列之應用系統權限框 → 於展開之清單點「讀金鑰」/「Read tokens」→ 點功能列之儲存鈕（清單仍開啟）→ 於成功訊息點「確認」/「OK」。
    - 驗證：
      1. 語意：操作前 test-token-4 呼叫後台金鑰清單（kpfun `getTokensList`）被拒；勾選後清單未關閉即出現儲存鈕；出現「Save tokens successfully」/「儲存金鑰數據成功」之 System message modal；DB 中 test-token-4 之 perms 為 `['readTokens']`；儲存後 test-token-4 呼叫 `getTokensList` 立即成功（端到端不變式）。
      2. 視覺：`E2E-005-1-click-perms`（框住 test-token-4 列之應用系統權限框整顆，內含「讀使用者」標籤）→ `E2E-005-2-perms-list`（框住展開之權限清單浮層整個，含標頭「應用系統權限」）→ `E2E-005-3-check-read-tokens`（框住清單中「讀金鑰」整列，含勾選框、名稱與「等同管理者權限」提示）→ `E2E-005-4-read-tokens-checked`（框住權限清單浮層整個，「讀金鑰」已勾選）→ `E2E-005-5-click-save`（框住功能列之儲存鈕整顆，權限清單仍開啟）→ `E2E-005-6-save-success-modal`（框住成功訊息之對話框面板）→ `E2E-005-7-perms-result`（點「確認」關閉後，框住 test-token-4 列之應用系統權限框，含「讀使用者」「讀金鑰」標籤）。
    - 雙語：eng / cht 各一輪。
    - 清理：移除本檔特化 admin user / admin token / 6 筆 test token（含本案寫入之 perms），保留 base seed；回驗 tokens 表無 `id-test-token-*` 列。
    - 備註：權限框為 `LayoutContentTokens.vue` 之 cell-render `perms` 內 WPopup 觸發區，清單浮層 teleport 至 body；清單項之可點層為 WInputCheckbox 每項之 inline-block 容器；勾選與該列現值不同即標記已修改（`setPermsDraft`），按儲存時先寫回清單勾選（`commitPermsDraft`）。端到端不變式以後台 kpfun 驗 app token 之實際能力（`server/procCore.mjs` 之 `_checkTokenByObj`）。與 E2E-006 為勾選↔取消勾選之對稱路徑。1280 寬時本欄於捲軸歸位時不在可視範圍（表格多「用途」「名稱」欄之後；原載「於捲軸歸位即完整可見，不以程式捲動帶入」不成立，2026-10-24 ADR-095），以測試共用之 `ensureColumnVisible` 橫向捲動帶入（使用者亦須如此操作）；點「確認」關閉訊息後捲軸歸位，結果圖前再捲入。

- **E2E-006**
  - title: 取消應用系統金鑰之權限並儲存（以讀統計為例）
  - description: 管理員從主選單點選「金鑰清單」後，點擊應用系統金鑰列於「應用系統權限」欄的權限框，展開清單後取消勾選不再需要的權限，例如「讀統計」；功能列隨即出現紅色圓形、提示文字為「儲存變更」的儲存按鈕，點擊後畫面顯示「儲存金鑰數據成功」，點「確認」關閉，該列權限框即不再列出「讀統計」，該應用系統自此無法再讀取統計資料，其餘已授予的權限不受影響。取消勾選只在點擊儲存按鈕後才寫入。基本權限「讀使用者」無法取消；若要讓應用系統完全停用，請勾選該列後刪除並儲存。儲存時若顯示「儲存金鑰數據失敗」接失敗原因，重新登入後再操作即可。適合於應用系統不再需要某項後台功能時收回權限。
  - flow:
    - 測試資料：同 E2E-001；目標列為 test-token-5（`isApp='y'`、perms 讀金鑰＋讀統計）。

## spec 規則摘要

- **多人同時編輯**（2026-10-23，原則 10 選項 P；跨清單共通規則與案例見 `流程_多人同時編輯.md`）：應用系統金鑰列（`isApp='y'`）嚴格整表比對；session 列（登入新增、續期改 `timeEnd`、登出或封鎖刪除）逐列寬鬆比對——只比對管理員有改或刪之列，載入後才登入者不刪（修正：原存舊清單會刪掉他們而使其被登出）、載入後已登出或被封鎖撤銷者不復活（修正：原會被當新增列寫回，繞過自動封鎖）、系統續期而管理員未動之列不寫（修正：原以舊到期時間蓋回）、管理員有動而庫內已變者整次拒收。E2E-003「勾選金鑰刪除並儲存以撤銷登入」行為不變（帶基準之後台路徑）。（修改留痕 2026-10-24，ADR-095：原載「與 E2E-002『勾選 isApp 升級』行為不變」「不帶基準……只刪／改應用系統金鑰列（含送出 `isApp='y'` 之升級）……新增列僅限應用系統金鑰（`isApp='y'`，含鑄造，ADR-084）」已不成立——勾選升級路徑關閉〔E2E-002 廢止〕，清單存檔一律不得新增應用系統金鑰或升級 session 列，新增改走「新增應用系統金鑰」〔E2E-008 / E2E-009〕。）不帶基準（app 權杖直呼、舊版頁面）只刪／改應用系統金鑰列之權限，session 列不刪不覆蓋；DB 既有之 `perms` 毀損值、null 或缺欄之舊列於存回時依 ADR-069 正規化為空陣列（既有行為，`api-apptoken-perms` PERM-A-005 守護；外審 sol#8 建議之「原樣重送零寫入」與之衝突，不採）。**清單存檔（帶或不帶基準）一律不得新增庫內不存在之 session 列**（`isApp` 非 `'y'`；ADR-092，2026-10-23 sso-verify01 註記 1）：session 金鑰只由登入產生，送出含此類列者整次拒收（零寫入，同批之其他變更亦不寫），回語系鍵 `tokenSessionAddNotAllowed`（「不可新增登入權杖」），不回顯值；因此不帶基準者（app 權杖直呼、舊版頁面）送回已被登出／撤銷之舊 session 列，不會使其復活（帶基準時，基準內而管理員未動、其後被撤銷之列照舊略過，不屬新增）。下一 major 起後台必帶基準（2026-10-23 外審 sol#1、#2、#8；sol#1 之 session 列復活已由 ADR-092 收回）。
- **應用系統金鑰之兩種用途與生命週期**（2026-10-24，ADR-095；業主裁示 2026-10-24）：①**使用者用途**（`appUsage='user'`）綁定一位既有啟用使用者，代表該使用者本人，授權同該使用者之登入 token（含管理者之 `funCheckAdmin`），不適用 perms；每次使用即時依所綁使用者目前狀態（存在、啟用、未封鎖、帳號未到期、已驗證）判定，不符即不可用，狀態恢復後即可再用（封鎖、帳號到期、未驗證及直接改庫之停用皆屬此類，金鑰列不動）；**停用－恢復例外**：管理員經後台使用者清單「停用」或刪除使用者時，系統一併撤銷（刪列）該使用者之登入 token 與綁其之使用者用途金鑰，重新啟用後不恢復，須重新核發（`test/api-apptoken-usage.test.mjs` REV[停用]）；②**系統服務用途**（`appUsage='system'`，升級前既有應用系統金鑰視同此用途）不綁使用者，`getUserByToken` 回應用系統身分（`id=app:<金鑰主鍵>`、`isAdmin='y'`、`name`＝金鑰名稱），授權依 perms（ADR-069），不可變更密碼，建立者被停用或刪除不影響。兩種用途皆不設期限（列表顯示「不設期限」）、`refreshToken` 一律拒收（`tokenAppNoRefresh`）。鑄造只能經 `createAppToken`（E2E-008 / E2E-009）；列表只能改系統服務用途之權限與刪除；用途、名稱、所綁使用者、金鑰字串、到期時間鑄造後不可改。
- **權限**：`getTokensList` / `updateTokensList` 之使用者 token 須為管理者（`funCheckAdmin`）；應用系統金鑰依其 perms 須具 `readTokens` / `writeTokens`（ADR-069）；皆不足時對外同為 `tokenExpired`。
- **應用系統權限**（ADR-069）：權限字串 7 個（`readUsers` / `writeUsers` / `readTokens` / `writeTokens` / `readIps` / `writeIps` / `readStats`），多元素為聯集，讀寫互不蘊含；`readUsers` 為基本權限恆具備、不可取消；perms 未設定＝只有基本權限；`writeUsers` / `readTokens` / `writeTokens` 可取得管理者權限，清單以「等同管理者權限」標註。
- **權限清單之寫入時機**：勾選即標記已修改（儲存鈕出現），但只寫入前端表格之草稿；關閉清單或按儲存時寫回該列，按儲存才寫入 DB；非編輯模式清單唯讀；表格重建時草稿捨棄。
- **標準圖通則**：存放 `test/pics/tokens/`，檔名 `tokens-{eng,cht}-E2E-NNN[-<序>-<名>].png`；E2E-005 起每步兩張（點擊前框住要點之元素、點擊後框住有反應之元素），一圖一框；權限清單浮層框其面板整個（含標頭），框線不蓋背後表格之內容：背後有內容處，框線置於浮層內容與背後內容之間隙正中（退入浮層內距）；四周空白處照常外擴。權限清單單一項目之框（E2E-005-3、E2E-006-3）：框住該項之勾選框、名稱與說明；清單行距 24px、項目間隙約 1px，框線置於本項與上下相鄰項之可見內容（勾選框與文字）間隙正中，不壓到相鄰項與本項之文字（2026-09-28 改：原載「與上下相鄰項之交界正中」，交界以元素框計會受透明內距影響，改以可見內容之間隙計）。
  - 修改留痕（2026-09-28）：原載「紅框 5px 且外擴 6px 必覆蓋上下相鄰項邊緣約 5px，業主 2026-09-27 裁示維持現狀」為誤記——業主明示「亂框亂壓導致遮蔽有效資訊或使用者誤解就是問題、就該修」；改為框線置於交界（srcPack `itemsUnionBox` fit 之相鄰夾邊），浮層框線畫在內側（浮層規則），並重產 E2E-005／006／007 受影響之圖。同日再改：「浮層框線畫在內側」使左緣框線距勾選框僅 1px，改為框線置於浮層內容與背後內容之間隙正中、四周空白照常外擴；相鄰夾邊改以可見內容之間隙計。
- **粒度**：操作結果（成功 / 失敗）一律 `showCheckYes` 持久 modal（須確認讀過、可做 e2e pixel + 語意斷言）；非預期例外才用 `$alert` toast。
- **邊界**：`isError` 恆為 `''`，前端驗證攔截分支為死碼；無「手動新增」列。刪除某列即撤銷該 session。
- **新增列（ADR-095 起一律拒收，鑄造改走 `createAppToken`）**：清單存檔含庫內不存在之列〔不論 `isApp`〕整批拒收——`isApp='y'` 者回 `tokenAppAddNotAllowed`（「不可經儲存清單新增應用系統金鑰，請改用「新增應用系統金鑰」，本次未儲存任何變更」），`isApp` 非 `'y'` 者回 `tokenSessionAddNotAllowed`（`test/unit-saveBaseline.test.mjs` SB-T07、SB-T16~T19、`test/api-apptoken-usage.test.mjs` LIST、`test/api-concurrency.test.mjs` CC-A-022~024）；既有列之 `isApp` 由 `n` 改 `y`（升級）回 `tokenSessionUpgradeNotAllowed`，應用系統金鑰之 `token`／`userId`／`isApp`／`timeEnd` 被改動回 `tokenAppLocked`，使用者用途金鑰被送入 `perms` 回 `tokenAppPermsNotForUser`；皆整批零寫入。新增應用系統金鑰之唯一入口為 kpfun `createAppToken`（管理員或具 `writeTokens` 之系統服務金鑰；權杖字串由伺服端產生、不給期限、擁有者＝建立者；`procCore.mjs:checkTokenAndCreateAppToken`，`lockSave` 防連點／重送）。（修改留痕 2026-10-24：原載「新增列（僅直打 API；僅限應用系統金鑰之鑄造，ADR-042、ADR-092）：新增列須 `isApp='y'`……擁有者（`userId`）依送入值寫入——寫入層會把 `userId` 欄改寫為寫入參數（視為建立者），本清單依擁有者分組、以擁有者為參數寫入（ADR-084）」為 ADR-095 前之行為，已由 ADR-095 取代；ADR-084 之擁有者保留機制改由 `createAppToken` 沿用。）
- **契約**：Save 前開 loading、`finally` 一處關 loading；每個 `await showCheckYes(...)` 前先關 loading（modal 阻斷，避免 loading 疊著）。
- **寫入前驗證**（ADR-021 / ADR-081）：perms 驗證之後、任何寫入之前，依序驗列格式（rows 為陣列；主鍵非空、表內不重複、UTF-8 不超過 1978 位元組 → `invalidRows`）與新增 / 修改列之欄位值不會被 clearXSS 改寫（`htmlMarkupNotAllowed`）；與 DB 相同之列不寫入、不檢查。
- **寫入失敗**（ADR-080）：perms 驗證全過後之寫入階段依刪除、新增、修改之順序寫入，任一步失敗即停止後續步驟、回 `saveWriteFail`，其前已寫入者不回滾；金鑰清單之 30 秒快取（統計頁所讀）不論寫入成敗皆於寫入階段後清除。
